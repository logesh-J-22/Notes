# Ansible `zip` and `zip_longest` Filters

## Overview

The **`zip`** and **`zip_longest`** filters combine two or more lists by grouping elements that share the same index.

These filters are useful when:

- Pairing related data from multiple lists.
- Creating tuples for loops.
- Combining interface names with IP addresses.
- Building dictionaries from separate key and value lists.
- Processing inventory variables stored in separate lists.

The filters are based on Python's built-in `zip()` and `itertools.zip_longest()` functions.

---

# `zip`

The **`zip`** filter combines elements from multiple lists until the **shortest list** is exhausted.

## Syntax

```jinja2
{{ list1 | zip(list2) }}
```

Multiple lists:

```jinja2
{{ list1 | zip(list2, list3) }}
```

---

# `zip_longest`

The **`zip_longest`** filter also combines multiple lists, but continues until the **longest list** is exhausted.

If one list runs out of elements, missing values are filled with:

- `None` (default)
- A custom value using **`fillvalue`**

## Syntax

```jinja2
{{ list1 | zip_longest(list2) }}
```

With multiple lists:

```jinja2
{{ list1 | zip_longest(list2, list3) }}
```

With a fill value:

```jinja2
{{ list1 | zip_longest(list2, fillvalue='N/A') }}
```

# Demo Playbook

```yaml
---
- name: Demo on Zip
  hosts: R1
  gather_facts: false

  vars:

    device_name:
      - CSR1
      - CSR2
      - CSR3

    mgmt_address:
      - 192.168.71.11
      - 192.168.71.12
      - 192.168.71.13

    interfaces:
      - FastEthernet0/0
      - FastEthernet1/0
      - FastEthernet2/0

    ip_address:
      - 10.10.10.10
      - 20.20.20.20
      - 30.30.30.30

    subnet_mask:
      - 255.255.255.255
      - 255.255.255.0

  tasks:

    - name: Pair devices with management IPs
      debug:
        msg: "{{ device_name | zip(mgmt_address) | list }}"

    - name: Zip interfaces using zip_longest
      debug:
        msg: "{{ interfaces | zip_longest(ip_address, subnet_mask) | list }}"

    - name: Zip interfaces using fillvalue
      debug:
        msg: "{{ interfaces | zip_longest(ip_address, subnet_mask, fillvalue='255.255.255.0') | list }}"
```

# Understanding `zip`

## Example 1

```jinja2
{{ device_name | zip(mgmt_address) | list }}
```

### Step 1

List 1

```yaml
CSR1
CSR2
CSR3
```

List 2

```yaml
192.168.71.11
192.168.71.12
192.168.71.13
```

---

### Step 2

Pair elements with the same index.

| Index | Device | Management IP |
|------:|---------|---------------|
| 0 | CSR1 | 192.168.71.11 |
| 1 | CSR2 | 192.168.71.12 |
| 2 | CSR3 | 192.168.71.13 |

---

### Output

```yaml
[
  ["CSR1", "192.168.71.11"],
  ["CSR2", "192.168.71.12"],
  ["CSR3", "192.168.71.13"]
]
```

Visual representation

```text
device_name          mgmt_address

CSR1  ─────────────► 192.168.71.11
CSR2  ─────────────► 192.168.71.12
CSR3  ─────────────► 192.168.71.13
```

# Example 2 – Three Lists

```jinja2
{{ interfaces | zip(ip_address, subnet_mask) | list }}
```

Input

```yaml
interfaces

- Fa0/0
- Fa1/0
- Fa2/0

ip_address

- 10.10.10.10
- 20.20.20.20
- 30.30.30.30

subnet_mask

- 255.255.255.255
- 255.255.255.0
```

Since `subnet_mask` contains only **2 elements**, `zip()` stops after the second item.

Output

```yaml
[
  ["Fa0/0","10.10.10.10","255.255.255.255"],
  ["Fa1/0","20.20.20.20","255.255.255.0"]
]
```

The third interface is ignored.

---

# Why Does `zip()` Stop Early?

The `zip` filter always stops when the **shortest list** ends.

Example

```text
List A

A
B
C

List B

1
2
```

Result

```text
(A,1)

(B,2)
```

Element **C** has no matching value, so it is discarded.

---

# Understanding `zip_longest`

`zip_longest` continues until the **longest list** is exhausted.

Missing values are replaced with **None** by default.

---

## Example

```jinja2
{{ interfaces | zip_longest(ip_address, subnet_mask) | list }}
```

Output

```yaml
[
  ["FastEthernet0/0","10.10.10.10","255.255.255.255"],
  ["FastEthernet1/0","20.20.20.20","255.255.255.0"],
  ["FastEthernet2/0","30.30.30.30",null]
]
```

Notice the last tuple.

The subnet mask list has no third value, so Ansible inserts **null** (`None`).

---

# Using `fillvalue`

Instead of `None`, you can specify your own value.

```jinja2
{{ interfaces | zip_longest(ip_address,
                             subnet_mask,
                             fillvalue='255.255.255.0') | list }}
```

Output

```yaml
[
  ["FastEthernet0/0","10.10.10.10","255.255.255.255"],
  ["FastEthernet1/0","20.20.20.20","255.255.255.0"],
  ["FastEthernet2/0","30.30.30.30","255.255.255.0"]
]
```

The missing subnet mask is replaced with the specified value.

---

# Understanding `fillvalue`

`fillvalue` is an optional parameter of `zip_longest`.

Syntax

```jinja2
zip_longest(list2, fillvalue=value)
```

Example

```jinja2
{{ ['A','B','C'] | zip_longest([1], fillvalue='N/A') | list }}
```

Output

```yaml
[
  ["A",1],
  ["B","N/A"],
  ["C","N/A"]
]
```

# Using `zip` in Loops

One of the most common uses of `zip` is looping over two related lists.

```yaml
- debug:
    msg: "{{ item.0 }} --> {{ item.1 }}"

  loop: "{{ device_name | zip(mgmt_address) | list }}"
```

Output

```text
CSR1 --> 192.168.71.11
CSR2 --> 192.168.71.12
CSR3 --> 192.168.71.13
```

Here:

- `item.0` → First list element
- `item.1` → Second list element

# Creating Dictionaries

Suppose

```yaml
keys:

- hostname
- ip
- os

values:

- R1
- 10.10.10.10
- ios
```

Create a dictionary:

```jinja2
{{ dict(keys | zip(values)) }}
```

Output

```yaml
hostname: R1
ip: 10.10.10.10
os: ios
```

This is a very common pattern in Ansible.

# `zip` vs `zip_longest`

| Feature | `zip` | `zip_longest` |
|---------|-------|---------------|
| Stops at shortest list | ✅ | ❌ |
| Stops at longest list | ❌ | ✅ |
| Missing values become `None` | ❌ | ✅ |
| Supports `fillvalue` | ❌ | ✅ |
| Best when lists are equal length | ✅ | ✅ |
| Best when lengths differ | ❌ | ✅ |

# Best Practices

- Use **`zip`** when all lists should have the same number of elements.
- Use **`zip_longest`** when lists may have different lengths.
- Specify a **`fillvalue`** when missing values should have a meaningful default instead of `None`.
- Append **`| list`** because `zip` and `zip_longest` return iterators.

---

# Summary

| Expression | Result |
|------------|--------|
| `zip(list2)` | Combine lists until the shortest list ends |
| `zip(list2, list3)` | Combine three lists together |
| `zip_longest(list2)` | Combine lists until the longest list ends |
| `zip_longest(..., fillvalue='N/A')` | Replace missing values with a custom value |
| `dict(keys \| zip(values))` | Convert two lists into a dictionary |

---

# Key Takeaway

The **`zip`** and **`zip_longest`** filters are powerful tools for combining related lists in Ansible. Use **`zip`** when all lists are expected to be the same length, and use **`zip_longest`** when list lengths may differ. The `fillvalue` parameter in `zip_longest` allows you to substitute meaningful defaults for missing values, making it especially useful when building structured configuration data.
