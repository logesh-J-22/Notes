# Ansible `ios_config` - Understanding `after`

## Overview

The `after` parameter in the `cisco.ios.ios_config` module defines commands that are executed **after** the commands specified in `lines`.

It is used for adding follow-up configuration commands after the main configuration has been applied.

The execution order of `ios_config` is:

```text
before
   ↓
parents
   ↓
lines
   ↓
after
```

---

# Basic Syntax

```yaml
cisco.ios.ios_config:
  parents:
    - configuration-context
  lines:
    - main-configuration-command
  after:
    - follow-up-command
```

---

# Example Playbook

```yaml
---
- name: Demo on after
  hosts: ciscoIOS
  gather_facts: false

  tasks:
    - name: Config on after
      cisco.ios.ios_config:
        parents: "interface {{ item.name }}"
        lines:
          - "description {{ item.description }}"
        after:
          - shutdown
          - no logging event link-status
      loop: "{{ interface_details }}"
      register: output

    - name: show the interface configured
      ansible.builtin.debug:
        msg: "{{ output }}"
```

---

# Understanding the Playbook

## Variables Used

Example `interface_details`:

```yaml
interface_details:
  - name: FastEthernet0/0
    description: Connection to Pc1
    ip_address: 192.168.90.11
    subnet_mask: 255.255.255.0

  - name: FastEthernet2/0
    description: Connection to Pc2 - Faulty
    ip_address: 192.168.91.11
    subnet_mask: 255.255.255.0
```

The loop processes one interface at a time.

---

# Understanding `parents`

```yaml
parents: "interface {{ item.name }}"
```

`parents` defines the Cisco IOS configuration mode where the commands should run.

For the first iteration:

```yaml
item.name: FastEthernet0/0
```

Ansible converts:

```yaml
parents: "interface {{ item.name }}"
```

into:

```text
interface FastEthernet0/0
```

For the second iteration:

```text
interface FastEthernet2/0
```

Equivalent Cisco CLI:

```text
Router(config)# interface FastEthernet0/0
Router(config-if)#
```

---

# Understanding `lines`

```yaml
lines:
  - "description {{ item.description }}"
```

`lines` contains the main configuration commands.

For FastEthernet0/0:

```text
description Connection to Pc1
```

For FastEthernet2/0:

```text
description Connection to Pc2 - Faulty
```

---

# Understanding `after`

```yaml
after:
  - shutdown
  - no logging event link-status
```

Commands under `after` execute **after** the commands under `lines`.

For example:

```yaml
lines:
  - description Connection to Pc2 - Faulty

after:
  - shutdown
  - no logging event link-status
```

Ansible executes:

```text
configure terminal

interface FastEthernet2/0

description Connection to Pc2 - Faulty

shutdown

no logging event link-status
```

The execution sequence:

```text
1. Enter interface configuration mode
             |
             v
2. Execute lines
   description Connection to Pc2 - Faulty
             |
             v
3. Execute after
   shutdown
   no logging event link-status
```

---

# Understanding Actual Output

Example Ansible output:

```text
changed: [R1] => (item={
'name': 'FastEthernet2/0',
'description': 'Connection to Pc2 - Faulty'
})
```

The registered output shows:

```text
commands:
  - interface FastEthernet2/0
  - description Connection to Pc2 - Faulty
  - shutdown
  - no logging event link-status
```

This proves that:

```text
parents
    ↓
lines
    ↓
after
```

is the execution order.

---

# Why Did Only One Interface Change?

Example:

```text
ok: [R1] => FastEthernet0/0

changed: [R1] => FastEthernet2/0
```

`ios_config` is idempotent.

If the configuration already exists:

```text
description Connection to Pc1
shutdown
no logging event link-status
```

Ansible does nothing.

Result:

```text
changed: false
```

If the configuration is different:

```text
description Connection to Pc2
```

changed to:

```text
description Connection to Pc2 - Faulty
```

Ansible applies the change.

Result:

```text
changed: true
```

---

# Can `after` Commands Be Added to `lines`?

Yes, technically.

Example:

```yaml
lines:
  - description Connection to Pc1
  - shutdown
  - no logging event link-status
```

This will work.

The router receives:

```text
interface FastEthernet0/0
description Connection to Pc1
shutdown
no logging event link-status
```

However, separating them can improve readability:

```yaml
lines:
  - description Connection to Pc1

after:
  - shutdown
  - no logging event link-status
```

# Common Use Cases of `after`

## 1. Save Configuration

Example:

```yaml
after:
  - end
  - write memory
```

Execution:

```text
interface FastEthernet0/0
description Connection to PC1
end
write memory
```

---

## 2. Apply Follow-up Interface Settings

Example:

```yaml
lines:
  - description Server Interface

after:
  - shutdown
  - no logging event link-status
```

---

## 3. Add Additional Configuration After Main Changes

Example:

```yaml
lines:
  - ip address 192.168.1.1 255.255.255.0

after:
  - no shutdown
```

---

# Difference Between `lines` and `after`

|Feature|`lines`|`after`|
|---|---|---|
|Purpose|Main configuration commands|Commands executed after `lines`|
|Execution time|First|Second|
|Uses `parents` context|Yes|Yes|
|Required|Usually|Optional|
|Example|`description PC1`|`shutdown`|

---

# Difference Between `parents` and `after`

|Parameter|Purpose|
|---|---|
|`parents`|Defines **where** commands execute|
|`lines`|Defines **what configuration** to apply|
|`after`|Defines **what happens after configuration**|

Example:

```yaml
parents:
  - interface FastEthernet0/0

lines:
  - description PC1

after:
  - shutdown
```

Means:

```text
Where?
→ interface FastEthernet0/0

Configure:
→ description PC1

After configuration:
→ shutdown interface
```

---

# `after` vs `save_when`

For saving configurations, prefer:

```yaml
save_when: modified
```

Example:

```yaml
cisco.ios.ios_config:
  lines:
    - hostname R1
  save_when: modified
```

Advantages:

- Saves only when changes occur.
    
- More Ansible-friendly.
    
- Avoids unnecessary configuration writes.
    

---

# Important Notes

## `after` does not automatically exit configuration mode

This:

```yaml
after:
  - shutdown
```

does not leave interface mode.

The command runs under:

```text
interface configuration mode
```

---

To exit:

```yaml
after:
  - end
```

To save:

```yaml
after:
  - end
  - write memory
```

---

# Key Takeaways

- `after` runs commands after `lines`.
    
- `after` executes inside the context defined by `parents`.
    
- `after` can contain any valid IOS configuration commands.
    
- `after` does not mean "exit configuration mode".
    
- Use `end` inside `after` if you want to leave configuration mode.
    
- Use `save_when: modified` instead of `write memory` for saving configurations.
    
- `ios_config` is idempotent, so commands are only sent when changes are required.
    

## Mental Model

Think of `ios_config` like a human engineer working on a Cisco router:

```text
Enter configuration mode
        |
        v
Go to the correct section (parents)
        |
        v
Apply main changes (lines)
        |
        v
Perform follow-up actions (after)
```
