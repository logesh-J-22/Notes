# When in Ansible

## Overview

The `when` keyword is used to **conditionally execute a task** based on the evaluation of one or more expressions. If the condition evaluates to `True`, the task runs. If it evaluates to `False`, the task is skipped.

The `when` statement helps make playbooks more intelligent by executing tasks only when required, avoiding unnecessary changes to managed devices.

---

## Syntax

```yaml
- name: Task Name
  <module_name>:
    ...
  when: <condition>
```

For multiple conditions:

```yaml
- name: Task Name
  <module_name>:
    ...
  when:
    - <condition_1>
    - <condition_2>
```

All listed conditions must evaluate to `True` for the task to execute.

---

## Example

The following playbook checks the status of the `FastEthernet0/0` interface. If the interface is found to be **down**, Ansible enters configuration mode and issues the `no shutdown` command.

```yaml
---
- name: Demo on when
  hosts: ciscoIOS
  gather_facts: false

  tasks:
    - name: Get the interface details
      cisco.ios.ios_command:
        commands:
          - "show interface FastEthernet0/0"
      register: Interface_status

    - name: Run using when
      cisco.ios.ios_command:
        commands:
          - "conf t"
          - "interface FastEthernet0/0"
          - "no shutdown"
          - "end"
      when:
        - "'down' in Interface_status['stdout'][0]"
```

---

## Explanation

### `register`

The output of the `show interface` command is stored in the variable `Interface_status`.

```yaml
register: Interface_status
```

Example output:

```yaml
Interface_status:
  stdout:
    - |
      FastEthernet0/0 is administratively down, line protocol is down
```

---

### `when`

The task is executed only if the specified condition evaluates to `True`.

```yaml
when:
  - "'down' in Interface_status['stdout'][0]"
```

This condition searches for the string `down` in the command output.

If:

- **True** → Execute the configuration commands.
    
- **False** → Skip the task.
    

---

## Execution Flow

```text
Run "show interface"
          │
          ▼
Store output in Interface_status
          │
          ▼
Evaluate the "when" condition
          │
     ┌────┴────┐
     │         │
  True       False
     │         │
     ▼         ▼
Execute     Skip task
commands
```

---

## Multiple Conditions

Multiple conditions can be specified as a list.

```yaml
when:
  - ansible_network_os == "cisco.ios.ios"
  - "'down' in Interface_status['stdout'][0]"
```

Both conditions must be `True` before the task executes.

---

## Using Logical Operators

### AND

```yaml
when:
  - condition1
  - condition2
```

or

```yaml
when: condition1 and condition2
```

---

### OR

```yaml
when: condition1 or condition2
```

Example:

```yaml
when: "'down' in Interface_status['stdout'][0] or 'administratively down' in Interface_status['stdout'][0]"
```

---

### NOT

```yaml
when: not condition
```

Example:

```yaml
when: "'up' not in Interface_status['stdout'][0]"
```

---

## Common Use Cases

Use `when` to:

- Configure an interface only if it is down.
    
- Skip tasks based on the operating system.
    
- Execute tasks only for specific device models.
    
- Run tasks only if a variable exists.
    
- Perform actions based on command output.
    
- Apply configurations only when required.
    

---

## Best Practices

- Use `register` to capture command output before evaluating conditions.
    
- Write clear and specific conditions.
    
- Use multiple conditions instead of long, complex expressions where possible.
    
- Use `when` to keep playbooks idempotent by avoiding unnecessary configuration changes.
    

---

## Key Points

- `when` is used for **conditional task execution**.
    
- A task runs only if the condition evaluates to `True`.
    
- If the condition is `False`, the task is skipped.
    
- Conditions can use registered variables, facts, inventory variables, and Jinja2 expressions.
    
- Multiple conditions can be combined using lists, `and`, `or`, and `not`.
    
- Using `when` improves playbook efficiency and helps maintain idempotency.
