# Ansible `combine` Filter

## Overview

The **`combine`** filter is a Jinja2 filter in Ansible that merges two or more dictionaries into a single dictionary.

It is commonly used to:

- Merge configuration variables
- Override default values
- Build dynamic configurations
- Combine role defaults with host-specific settings

---

# Playbook

```yaml
---
- name: Demo on Combine Filter
  hosts: R1
  gather_facts: false

  vars:
    basic_config:
      interface: FastEthernet0/0
      ip_address: 192.168.91.11
      subnet_mask: 255.255.255.0

    additonal_config:
      description: Connected to the Pc1
      mtu: 1510

  tasks:

    - name: Combine basic_config and additonal_config
      ansible.builtin.set_fact:
        full_config: "{{ basic_config | combine(additonal_config) }}"

    - name: Display the complete config
      ansible.builtin.debug:
        var: full_config
...
```

# Variables

## basic_config

Contains the base interface configuration.

```yaml
basic_config:
  interface: FastEthernet0/0
  ip_address: 192.168.91.11
  subnet_mask: 255.255.255.0
```

---

## additional_config

Contains extra interface parameters.

```yaml
additional_config:
  description: Connected to the Pc1
  mtu: 1510
```

---

# combine Filter

## Syntax

```jinja
dictionary1 | combine(dictionary2)
```

It merges **dictionary2** into **dictionary1** and returns a new dictionary.

---

## Example

Input

```yaml
basic_config:
  interface: FastEthernet0/0
  ip_address: 192.168.91.11

additional_config:
  mtu: 1510
  description: Connected to PC1
```

Using

```jinja
{{ basic_config | combine(additional_config) }}
```

Output

```yaml
interface: FastEthernet0/0
ip_address: 192.168.91.11
mtu: 1510
description: Connected to PC1
```

Both dictionaries are merged into one.

---

# Result of the Playbook

The `set_fact` task creates a new variable named `full_config`.

```yaml
full_config:
  interface: FastEthernet0/0
  ip_address: 192.168.91.11
  subnet_mask: 255.255.255.0
  description: Connected to the Pc1
  mtu: 1510
```

The original dictionaries remain unchanged.

# What Happens When Keys Are the Same?

Suppose

```yaml
basic_config:
  mtu: 1500

additional_config:
  mtu: 1510
```

Then

```jinja
{{ basic_config | combine(additional_config) }}
```

Result

```yaml
mtu: 1510
```

The value from the **second dictionary** overrides the value from the first.

Think of it as:

> "Later dictionaries take precedence."

---

# Combining More Than Two Dictionaries

You are not limited to merging only two dictionaries.

## Method 1 (Recommended)

Pass multiple dictionaries as a list.

```jinja
{{ dict1 | combine([dict2, dict3, dict4]) }}
```

### Example

```yaml
dict1:
  hostname: R1

dict2:
  ip: 10.1.1.1

dict3:
  location: Bangalore

dict4:
  os: IOS-XE
```

Merge them

```jinja
{{ dict1 | combine([dict2, dict3, dict4]) }}
```

Output

```yaml
hostname: R1
ip: 10.1.1.1
location: Bangalore
os: IOS-XE
```

This is the preferred approach because it is cleaner and easier to extend.

---

## Method 2

Chain multiple `combine` filters.

```jinja
{{ dict1
   | combine(dict2)
   | combine(dict3)
   | combine(dict4)
}}
```

This produces the same result but is more verbose.

---

# Which Value Wins?

Suppose

```yaml
dict1:
  mtu: 1500

dict2:
  mtu: 1510

dict3:
  mtu: 9000
```

Merge

```jinja
{{ dict1 | combine([dict2, dict3]) }}
```

Result

```yaml
mtu: 9000
```

The last dictionary has the highest priority.

Priority order

```
dict1 < dict2 < dict3
```

# Recursive Merge

By default, nested dictionaries are **replaced**, not merged.

Example

```yaml
dict1:
  interface:
    ip: 10.1.1.1
    mask: 255.255.255.0

dict2:
  interface:
    description: LAN
```

Normal combine

```jinja
{{ dict1 | combine(dict2) }}
```

Output

```yaml
interface:
  description: LAN
```

The original `ip` and `mask` values are lost because the entire `interface` dictionary is replaced.

---

## Recursive Combine

To merge nested dictionaries, use `recursive=True`.

```jinja
{{ dict1 | combine(dict2, recursive=True) }}
```

Output

```yaml
interface:
  ip: 10.1.1.1
  mask: 255.255.255.0
  description: LAN
```

Now the nested dictionaries are merged instead of replaced.

# Practical Example

Suppose a role defines default settings.

```yaml
default_config:
  hostname: Router
  logging: enabled
  mtu: 1500
```

A site overrides some values.

```yaml
site_config:
  hostname: Branch-R1
```

A host adds interface details.

```yaml
host_config:
  interface: GigabitEthernet0/0
```

Merge everything.

```jinja
{{ default_config | combine([site_config, host_config]) }}
```

Result

```yaml
hostname: Branch-R1
logging: enabled
mtu: 1500
interface: GigabitEthernet0/0
```

This pattern is commonly used to layer configuration data from defaults, environment-specific values, and host-specific overrides.

# Summary Table

| Expression | Description |
|------------|-------------|
| `dict1 \| combine(dict2)` | Merge two dictionaries |
| `dict1 \| combine([dict2, dict3])` | Merge multiple dictionaries |
| `dict1 \| combine(dict2, recursive=True)` | Merge nested dictionaries recursively |
| Duplicate keys | Value from the later dictionary overrides earlier ones |
| Original dictionaries | Remain unchanged; `combine` returns a new dictionary |

---

# Key Takeaways

- `combine` merges dictionaries into a new dictionary.
- The original dictionaries are not modified.
- When duplicate keys exist, the value from the later dictionary takes precedence.
- To merge more than two dictionaries, use `combine([dict2, dict3, ...])` or chain multiple `combine` filters.
- Use `recursive=True` when working with nested dictionaries to merge their contents instead of replacing them.
- `combine` is widely used for building flexible, layered configurations in Ansible.
