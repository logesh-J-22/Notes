
Before is used to remove/update the config before running any config

before  = What happens before configuration
parents = Where configuration happens
lines   = What configuration to apply
after   = What happens after configuration
match   = How Ansible checks existing configuration

in match we have 4:

>line : Compare individual configuration line
   strict : Compare line order exactly
exact : Exact comparison of configuration block
none : Do not compare; always send commands

In `cisco.ios.ios_config`, **`before`** and **`match`** control how Ansible handles configuration changes, but they solve different problems.

- **`before`** → runs commands **before** applying the configuration in `lines`.
    
- **`match`** → tells Ansible **how to compare the desired configuration with the existing device configuration** before deciding whether to send commands.
    

Let's understand both.

---

# 1. Understanding `before` in `ios_config`

## What is `before`?

The `before` parameter defines commands that should be executed **before** the commands in `lines`.

Execution order:

```text
before
   ↓
parents
   ↓
lines
   ↓
after
```

---

## Syntax

```yaml
cisco.ios.ios_config:
  before:
    - command1
    - command2
  lines:
    - command3
```

---

# Example 1: Remove old configuration before adding new configuration

Imagine an interface already has:

```text
interface FastEthernet0/0
 description OLD-CONNECTION
```

You want to replace it with:

```text
description Connection to PC1
```

You can use:

```yaml
- name: Configure interface description
  cisco.ios.ios_config:
    parents:
      - interface FastEthernet0/0
    before:
      - no description
    lines:
      - description Connection to PC1
```

---

## Cisco CLI equivalent

Ansible performs:

```text
configure terminal

interface FastEthernet0/0

no description

description Connection to PC1
```

Execution flow:

```
parents
   |
   v
interface FastEthernet0/0

before
   |
   v
no description

lines
   |
   v
description Connection to PC1
```

---

# Example 2: Clearing existing ACL before applying new ACL

Suppose you have:

```text
access-list 10 permit 192.168.1.0
access-list 10 permit 10.10.10.0
```

You want a clean ACL.

Playbook:

```yaml
- name: Replace ACL configuration
  cisco.ios.ios_config:
    before:
      - no access-list 10
    lines:
      - access-list 10 permit 172.16.0.0
```

Execution:

```text
configure terminal

no access-list 10

access-list 10 permit 172.16.0.0
```

---

# Why use `before`?

`before` is useful when:

- Existing configuration must be removed first.
    
- You want to reset a configuration section.
    
- A command conflicts with existing settings.
    

Examples:

|Situation|Use `before`|
|---|---|
|Remove old ACL|`no access-list 10`|
|Remove old route|`no ip route ...`|
|Remove old description|`no description`|
|Clear old banner|`no banner motd`|

# 2. Understanding `match` in `ios_config`

## What is `match`?

The `match` parameter controls how Ansible compares:

```
Desired configuration
        |
        |
Existing running configuration
```

before deciding whether to send commands.

It helps Ansible maintain **idempotency**.

---

## Syntax

```yaml
cisco.ios.ios_config:
  lines:
    - hostname R1
  match: exact
```

---

# Available `match` options

`ios_config` supports:

|Value|Meaning|
|---|---|
|`line`|Compare individual configuration lines|
|`strict`|Compare line order exactly|
|`exact`|Exact comparison of configuration block|
|`none`|Do not compare; always send commands|

---

# Default Behavior

Default:

```yaml
match: line
```

Ansible checks each line individually.

Example:

Desired:

```text
interface FastEthernet0/0
 description PC1
 ip address 192.168.1.1 255.255.255.0
```

Device has:

```text
interface FastEthernet0/0
 description PC1
```

Ansible only sends:

```text
ip address 192.168.1.1 255.255.255.0
```

because description already exists.

---

# `match: line`

Example:

```yaml
- name: Configure interface
  cisco.ios.ios_config:
    parents:
      - interface FastEthernet0/0
    lines:
      - description PC1
      - ip address 192.168.1.1 255.255.255.0
    match: line
```

Comparison:

```
description PC1
      |
      √ Exists

ip address
      |
      X Missing

Only IP address is configured
```

---

# `match: strict`

`strict` checks:

1. Command exists
    
2. Command order is the same
    

Example:

Desired:

```yaml
lines:
  - description PC1
  - ip address 192.168.1.1 255.255.255.0
```

Device:

```text
ip address 192.168.1.1 255.255.255.0
description PC1
```

The commands exist, but the order is different.

With:

```yaml
match: strict
```

Ansible considers it different and updates.

---

# `match: exact`

`exact` requires the configuration block to be exactly the same.

Example:

Desired:

```text
interface FastEthernet0/0
 description PC1
 ip address 192.168.1.1 255.255.255.0
```

Device:

```text
interface FastEthernet0/0
 description PC1
 ip address 192.168.1.1 255.255.255.0
 shutdown
```

With:

```yaml
match: exact
```

Ansible detects the extra:

```text
shutdown
```

and considers it different.

---

# `match: none`

Example:

```yaml
- name: Always execute command
  cisco.ios.ios_config:
    lines:
      - do something
    match: none
```

Ansible does not check the existing configuration.

It always sends the command.

Use carefully because it can reduce idempotency.

---

# Combining `before`, `match`, `parents`, `lines`, `after`

Example:

```yaml
- name: Configure interface
  cisco.ios.ios_config:
    parents:
      - interface FastEthernet0/0

    before:
      - no description

    lines:
      - description Server_Interface

    after:
      - no shutdown

    match: line
```

Execution:

```
Enter interface mode
        |
        v
before:
 no description

        |
        v

lines:
 description Server_Interface

        |
        v

after:
 no shutdown
```

---

# Complete Execution Model

A complete `ios_config` task works like this:

```
                 Device Configuration
                         |
                         v
                  match comparison
                         |
              ---------------------
              |                   |
          Difference           No change
              |
              v
        Execute before
              |
              v
        Enter parents
              |
              v
        Apply lines
              |
              v
        Execute after
```

---

# Difference Between `before` and `after`

|Parameter|Purpose|Runs|
|---|---|---|
|`before`|Prepare device before configuration|Before `lines`|
|`lines`|Main configuration|Main action|
|`after`|Follow-up commands|After `lines`|

Example:

```yaml
before:
  - no shutdown

lines:
  - description Server

after:
  - shutdown
```

Execution:

```
no shutdown
description Server
shutdown
```

---

# Key Takeaways

## `before`

- Executes commands before `lines`.
    
- Useful for removing old configuration.
    
- Helps prepare the device for new configuration.
    

## `match`

- Controls configuration comparison.
    
- Helps Ansible decide whether changes are needed.
    
- Default is `line`.
    
- Controls idempotency behavior.
    

## Remember:

```
before  = What happens before configuration
parents = Where configuration happens
lines   = What configuration to apply
after   = What happens after configuration
match   = How Ansible checks existing configuration
```
