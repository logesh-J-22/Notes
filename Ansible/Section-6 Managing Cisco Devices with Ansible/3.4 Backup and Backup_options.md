Backup is used to take a backup of the running config of the device before applying any config to it.

Backup options (dir_path and filename) used to change the default directory path and file name of the backup that is taken.

# Ansible: Backup and `backup_options` (Cisco IOS)

## 📌 Overview

When making configuration changes to Cisco IOS devices using the `cisco.ios.ios_config` module, Ansible can automatically create a backup of the device's running configuration before applying any changes.

This provides an easy rollback reference and helps maintain configuration history.

---

# Backup Parameter

The `backup` parameter enables automatic configuration backup.

```yaml
backup: yes
```

### What it does

- Retrieves the current running configuration.
    
- Saves it as a file on the Ansible control node.
    
- Creates the backup **before** configuration changes are applied.
    
- Useful for:
    
    - Change management
        
    - Rollback reference
        
    - Auditing
        
    - Disaster recovery
        

---

# Backup Options

The `backup_options` parameter allows customization of where and how backup files are stored.

```yaml
backup_options:
  dir_path: "{{ playbook_dir }}/config_backup/"
  filename: "{{ inventory_hostname }}_config_{{ lookup('pipe','date +%d-%m-%Y-%H-%M-%S') }}.cfg"
```

## Available Options

### 1. `dir_path`

Specifies the directory where backup files will be saved.

```yaml
dir_path: "{{ playbook_dir }}/config_backup/"
```

### Explanation

- `playbook_dir`
    
    - Built-in Ansible variable.
        
    - Refers to the directory containing the current playbook.
        

Example:

```
project/
│
├── playbook.yml
└── config_backup/
```

All backup files will be stored inside `config_backup/`.

---

### 2. `filename`

Defines the backup file name.

```yaml
filename: "{{ inventory_hostname }}_config_{{ lookup('pipe','date +%d-%m-%Y-%H-%M-%S') }}.cfg"
```

This example creates filenames such as:

```
R1_config_04-08-2026-12-05-30.cfg
R2_config_04-08-2026-12-06-11.cfg
```

---

# Dynamic Variables Used

## `inventory_hostname`

Returns the current host name from the inventory.

Example inventory:

```ini
R1 ansible_host=192.168.1.10
R2 ansible_host=192.168.1.20
```

For host **R1**:

```yaml
{{ inventory_hostname }}
```

becomes

```
R1
```

---

## `lookup('pipe', ...)`

Executes a local shell command on the Ansible control node.

Example:

```yaml
lookup('pipe','date +%d-%m-%Y-%H-%M-%S')
```

Runs:

```bash
date +%d-%m-%Y-%H-%M-%S
```

Example output:

```
04-08-2026-12-05-30
```

This makes every backup filename unique.

# Complete Playbook

```yaml
---
- name: Demo on backup and backup options
  hosts: R1
  gather_facts: false

  tasks:

    - name: Run backup
      cisco.ios.ios_config:
        lines:
          - clock timezone EST 5 30

        backup: yes

        backup_options:
          dir_path: "{{ playbook_dir }}/config_backup/"
          filename: "{{ inventory_hostname }}_config_{{ lookup('pipe','date +%d-%m-%Y-%H-%M-%S') }}.cfg"

      register: output

    - name: Display output
      ansible.builtin.debug:
        msg: "{{ output }}"
```

---

# How the Playbook Works

```text
Start Playbook
      │
      ▼
Connect to Cisco Device
      │
      ▼
Download Current Running Configuration
      │
      ▼
Save Backup
(config_backup/R1_config_Date_Time.cfg)
      │
      ▼
Apply Configuration
(clock timezone EST 5 30)
      │
      ▼
Store Task Output
(register: output)
      │
      ▼
Display Output
```

# Benefits of Using `backup`

- Automatic configuration snapshots before changes.
    
- Easy rollback reference.
    
- Maintains configuration history.
    
- Supports change management and auditing.
    
- Protects against accidental misconfigurations.
    

---

# Key Points

|Parameter|Purpose|
|---|---|
|`backup`|Enables automatic configuration backup before changes.|
|`backup_options.dir_path`|Specifies the directory where backup files are stored.|
|`backup_options.filename`|Defines a custom backup filename.|
|`inventory_hostname`|Inserts the current device name into the filename.|
|`lookup('pipe', 'date ...')`|Appends the current date and time to create unique filenames.|
|`register`|Stores the module output for later use or debugging.|

---

# Expected Result

When the playbook runs:

1. Connects to the Cisco IOS device.
    
2. Saves the running configuration in the `config_backup/` directory.
    
3. Uses a unique filename based on the hostname and timestamp.
    
4. Applies the configuration change.
    
5. Displays the task output using the `debug` module.
