## Ansible `ios_config` `src` Parameter Notes

### Topic: Using `src` with `cisco.ios.ios_config`

The `src` parameter is used to load Cisco IOS configuration commands from a **file** and apply them to a network device.

Instead of writing configuration commands directly inside the playbook using `lines`, you can store the configuration in an external file and reference it using `src`.

---

## Example Playbook

```yaml
---
- name: Demo on Source
  hosts: R1
  gather_facts: false

  tasks:
    - name: Apply configuration from file
      cisco.ios.ios_config:
        src: templates/R1_interface_config.cfg
      register: output

    - name: Display Result
      ansible.builtin.debug:
        msg: "{{ output }}"

...
```

---

# How `src` Works

Example directory structure:

```
06_managing_cisco_devices_with_ansible/
│
├── Playbook/
│   └── 13_src.yaml
│
└── templates/
    └── R1_interface_config.cfg
```

The `src` path points to:

```
templates/R1_interface_config.cfg
```

Ansible reads this file and sends the configuration commands to the router.

---

# Configuration File Example

`templates/R1_interface_config.cfg`

```text
interface FastEthernet0/0
 description Connected to Computer1
 ip address 192.168.1.1 255.255.255.0
 no shutdown

interface FastEthernet0/1
 description Connected to Computer2
 ip address 192.168.2.1 255.255.255.0
 no shutdown
```

The file contains normal Cisco IOS configuration mode commands.

---

# Equivalent Configuration Without `src`

The same configuration can be written directly in the playbook:

```yaml
- name: Configure interface
  cisco.ios.ios_config:
    lines:
      - description Connected to Computer1
      - ip address 192.168.1.1 255.255.255.0
      - no shutdown
    parents:
      - interface FastEthernet0/0
```

Using `src` is cleaner when configurations become large.

---

# Advantages of Using `src`

### 1. Better organization

Keeps device configuration separate from automation logic.

Example:

```
Playbooks
   |
   └── Router configuration files
```

---

### 2. Easier maintenance

Instead of editing YAML:

```yaml
lines:
  - description LAN Interface
  - ip address 10.1.1.1 255.255.255.0
```

you edit a normal Cisco configuration file:

```text
interface FastEthernet0/0
 description LAN Interface
 ip address 10.1.1.1 255.255.255.0
```

---

### 3. Reusable configurations

The same configuration template can be applied to multiple routers.

Example:

```
templates/
├── R1_interface_config.cfg
├── R2_interface_config.cfg
└── R3_interface_config.cfg
```

---

# `src` vs `lines`

|Feature|`src`|`lines`|
|---|---|---|
|Configuration location|External file|Inside playbook|
|Best for|Large configs|Small changes|
|Readability|Better|Less readable for large configs|
|Reusability|High|Lower|
|Supports IOS hierarchy|Yes|Yes with `parents`|

---

# Registering Output

Your playbook uses:

```yaml
register: output
```

This stores the result returned by `ios_config`.

Example output contains:

```yaml
changed: true
commands:
  - interface FastEthernet0/0
  - description Connected to Computer1
```

You display it using:

```yaml
ansible.builtin.debug:
  msg: "{{ output }}"
```

---

# Important Notes

### 1. File path is relative to the playbook

Example:

Playbook location:

```
Playbook/13_src.yaml
```

Configuration file:

```
templates/R1_interface_config.cfg
```

Use:

```yaml
src: templates/R1_interface_config.cfg
```

---

### 2. The configuration file should contain IOS CLI syntax

Correct:

```text
interface FastEthernet0/0
 description Test Interface
```

Incorrect:

```yaml
interface:
  name: FastEthernet0/0
  description: Test Interface
```

---

### 3. `src` does not automatically save configuration

This:

```yaml
cisco.ios.ios_config:
  src: templates/R1_interface_config.cfg
```

only changes the running configuration.

To save:

```yaml
cisco.ios.ios_config:
  src: templates/R1_interface_config.cfg
  save_when: always
```

(For your Cisco 7200 GNS3 image, handle saving separately with `ios_command` because of the filename prompt issue.)

---

## Summary

- `src` loads IOS configuration from an external file.
    
- It is useful for large and reusable configurations.
    
- The file should contain normal Cisco IOS commands.
    
- `src` replaces the need for `lines` and `parents`.
    
- Use `register` to capture module output.
    
- Use `debug` to display the result.
    
- Saving configuration may require separate handling depending on the IOS image.
