# Ansible `group_vars` and `host_vars` Notes

## Overview

Ansible provides `group_vars` and `host_vars` to store variables outside the inventory file and playbooks.

They help organize variables based on:

- **Group level configuration** → `group_vars`
    
- **Individual host configuration** → `host_vars`
    

This keeps playbooks clean and makes variable management easier, especially in large environments.

# `group_vars`

## Purpose

`group_vars` stores variables that apply to a group of hosts.

Variables defined here are automatically loaded by Ansible based on inventory groups.

Syntax:

```
Inventory/
└── group_vars/
    └── <group_name>.yaml
```

Example:

```
Inventory/
└── group_vars/
    ├── all.yaml
    └── ciscoIOS/
        └── main.yaml
```

---

# `group_vars/all.yaml`

## Purpose

Variables inside `all.yaml` apply to **all hosts** in the inventory.

Example:

```yaml
ansible_user: admin
ansible_password: cisco123
```

These variables are available to:

- R1
    
- R2
    
- All other inventory hosts
    

Example inventory:

```yaml
all:
  children:
    ciscoIOS:
      hosts:
        R1:
        R2:
```

Both R1 and R2 inherit variables from:

```
group_vars/all.yaml
```

---

# Group-specific Variables

## Directory format

For a group named:

```
ciscoIOS
```

Variables can be stored as:

```
group_vars/
└── ciscoIOS/
    └── main.yaml
```

or:

```
group_vars/
└── ciscoIOS.yaml
```

Both formats are supported.

---

## Example

File:

```
Inventory/group_vars/ciscoIOS/main.yaml
```

Content:

```yaml
ansible_connection: network_cli
ansible_network_os: cisco.ios.ios
```

These variables apply only to hosts belonging to the `ciscoIOS` group.

Example:

```yaml
ciscoIOS:
  hosts:
    R1:
    R2:
```

Both R1 and R2 receive:

```yaml
ansible_connection: network_cli
ansible_network_os: cisco.ios.ios
```

---

# `host_vars`

## Purpose

`host_vars` stores variables specific to individual hosts.

Syntax:

```
Inventory/
└── host_vars/
    └── <hostname>.yaml
```

The filename must exactly match the inventory hostname.

---

## Example Structure

```
host_vars/
├── R1.yaml
└── R2.yaml
```

---

# Example `R1.yaml`

File:

```
Inventory/host_vars/R1.yaml
```

Content:

```yaml
hostname: Router-1
loopback_ip: 1.1.1.1
```

These variables are available only for R1.

---

# Example `R2.yaml`

File:

```
Inventory/host_vars/R2.yaml
```

Content:

```yaml
hostname: Router-2
loopback_ip: 2.2.2.2
```

These variables are available only for R2.

---

# Example Inventory

`Inventory.yaml`

```yaml
all:
  children:

    ciscoIOS:
      hosts:
        R1:
          ansible_host: 192.168.1.1

        R2:
          ansible_host: 192.168.1.2
```

Variable loading:

```
R1
 |
 |-- group_vars/all.yaml
 |
 |-- group_vars/ciscoIOS/main.yaml
 |
 └-- host_vars/R1.yaml


R2
 |
 |-- group_vars/all.yaml
 |
 |-- group_vars/ciscoIOS/main.yaml
 |
 └-- host_vars/R2.yaml
```

# Variable Precedence

When the same variable exists in multiple places, Ansible uses precedence rules.

Example:

`group_vars/all.yaml`

```yaml
ntp_server: 10.10.10.10
```

`group_vars/ciscoIOS/main.yaml`

```yaml
ntp_server: 20.20.20.20
```

`host_vars/R1.yaml`

```yaml
ntp_server: 30.30.30.30
```

For R1:

```
ntp_server = 30.30.30.30
```

because host-specific variables have higher precedence.

---

# Simplified Variable Priority

Highest priority:

```
Extra vars (-e)
        |
Task vars
        |
Host vars
        |
Group vars
        |
Inventory vars
        |
Role defaults
```

Example:

```bash
ansible-playbook playbook.yaml \
-e "ntp_server=40.40.40.40"
```

Overrides:

```
host_vars
group_vars
inventory variables
```

# Variable Loading Flow

When Ansible runs:

```bash
ansible-playbook Playbook/03_group_vars_and_host_vars.yaml
```

Ansible automatically:

1. Reads inventory:
    

```
Inventory/Inventory.yaml
```

2. Finds host groups:
    

```
ciscoIOS
```

3. Loads group variables:
    

```
group_vars/all.yaml
group_vars/ciscoIOS/main.yaml
```

4. Loads host variables:
    

```
host_vars/R1.yaml
host_vars/R2.yaml
```

5. Merges variables based on precedence.

# Best Practices

## Use `group_vars` for:

- Common credentials
    
- Network OS settings
    
- Connection settings
    
- Shared configuration
    

Example:

```yaml
ansible_connection: network_cli
ansible_network_os: cisco.ios.ios
```

---

## Use `host_vars` for:

- Unique IP addresses
    
- Device-specific values
    
- Loopback addresses
    
- Serial numbers
    
- Device roles
    

Example:

```yaml
loopback_ip: 10.1.1.1
router_id: R1
```

# Summary

|Feature|group_vars|host_vars|
|---|---|---|
|Scope|Group of hosts|Single host|
|Location|`group_vars/`|`host_vars/`|
|Filename|Group name|Host name|
|Example|`ciscoIOS/main.yaml`|`R1.yaml`|
|Used for|Common settings|Device-specific settings|
|Priority|Lower|Higher|

`group_vars` = "variables shared by many devices"

`host_vars` = "variables unique to one device"
