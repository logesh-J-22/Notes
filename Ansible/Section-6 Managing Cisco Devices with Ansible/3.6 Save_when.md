
save_when is used to save the running config to the startup config on the specific conditions.

> 1. ***always***: Always change the running-config to the startup config even there is no change
> 2. ***modified***: change the running-config to the startup config only if there is any change
> 3. ***changed***: Save only if a task changes are made
> 4. ***never***: Never save  automatically

# Ansible `save_when: always` (Cisco IOS)

## 📌 Overview

The `save_when` parameter in the `cisco.ios.ios_config` module controls when Ansible saves the device's **running configuration** into the **startup configuration**.

In Cisco IOS:

- **Running configuration** → Stored in RAM and active immediately.
    
- **Startup configuration** → Stored in NVRAM and loaded after reboot.
    

When Ansible modifies the running configuration, the change will be lost after a reboot unless it is saved.

Cisco IOS equivalent command:

```text
copy running-config startup-config
```

or:

```text
write memory
```

---

# Playbook Example

```yaml
---
- name: Demo on save_when
  hosts: R1
  gather_facts: false

  tasks:

    - name: Demo on save_when always
      cisco.ios.ios_config:

        lines:
          - description connected to computer1

        parents:
          - interface FastEthernet0/0

        save_when: always
```

# Compare `save_when` Options

|Option|Save Behavior|
|---|---|
|`always`|Always save after task execution.|
|`changed`|Save only when Ansible changes the configuration.|
|`modified`|Save only when running-config differs from startup-config.|
|`never`|Never save configuration.|

---

# When to Use `save_when: always`

Recommended for:

- Emergency configuration changes.
    
- Critical production changes.
    
- Environments where every execution must create a persistent configuration.
    
- Lab demonstrations.
    

Example:

```yaml
cisco.ios.ios_config:
  lines:
    - ip routing
  save_when: always
```

---

# Considerations

Although `always` guarantees configuration persistence, it may create unnecessary writes.

Every save operation writes to NVRAM:

```text
running-config
        |
        ▼
startup-config
```

For regular automation, `save_when: changed` is often preferred because it saves only when required.

|Parameter|Meaning|
|---|---|
|`save_when`|Controls automatic saving of running configuration.|
|`always`|Always saves configuration after task execution.|
|`parents`|Defines the configuration hierarchy.|
|`lines`|Commands applied inside the configuration mode.|
|Running-config|Current active configuration in RAM.|
|Startup-config|Saved configuration loaded after reboot.|
