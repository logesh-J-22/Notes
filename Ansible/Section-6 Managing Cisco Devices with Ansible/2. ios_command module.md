# Ansible `cisco.ios.ios_command` Module Notes

## What is `ios_command`?

The `cisco.ios.ios_command` module is used to execute **operational (EXEC mode)** commands on Cisco IOS devices.

It is mainly used for:

- Collecting device information
    
- Verifying interface status
    
- Checking routing tables
    
- Verifying configurations
    
- Performing health checks
    
- Waiting until a device reaches a desired state
    

> **Note:** This module **does not make configuration changes**. It only executes show and other EXEC commands. To configure devices, use `cisco.ios.ios_config`.

---

# Syntax

```yaml
- name: Execute show commands
  cisco.ios.ios_command:
    commands:
      - show version
      - show ip interface brief
```

---

# Common Parameters

## 1. `commands`

Specifies the list of commands to execute.

Example:

```yaml
commands:
  - show version
  - show ip route
  - show ip interface brief
```

Each command is executed **one after another**.

The output is stored in the same order.

For example,

```yaml
commands:
  - show version
  - show ip route
```

produces

```yaml
stdout:
  - output of show version
  - output of show ip route
```

Therefore,

```
result[0]
```

refers to the first command.

```
result[1]
```

refers to the second command.

---

## 2. `wait_for`

Used to verify whether the output contains a specific value.

Instead of failing immediately, Ansible waits until the condition becomes true.

Example

```yaml
wait_for:
  - result[0] contains up
```

Meaning:

> Wait until the output of the first command contains the word **up**.

---

### Multiple Conditions

```yaml
wait_for:
  - result[1] contains up
  - result[2] contains up
```

Meaning

- Check output of second command
    
- Check output of third command
    

---

## 3. `match`

Controls how multiple `wait_for` conditions are evaluated.

There are two options.

### `match: all` (Default)

Every condition must be true.

Example

```yaml
match: all

wait_for:
  - result[1] contains up
  - result[2] contains up
```

Both interfaces must be up.

If either fails, the task fails.

---

### `match: any`

Only one condition needs to be true.

Example

```yaml
match: any

wait_for:
  - result[1] contains up
  - result[2] contains up
```

If **either** interface is up, the task succeeds.

---

## 4. `interval`

Time (in seconds) between retries.

Example

```yaml
interval: 10
```

Ansible waits **10 seconds** before checking again.

---

## 5. `retries`

Maximum number of attempts.

Example

```yaml
retries: 10
```

Ansible checks the conditions up to **10 times**.

---

## 6. `register`

Stores the output of the module into a variable.

Example

```yaml
register: show_commands
```

Later,

```yaml
- debug:
    var: show_commands
```

prints the collected output.

---

# Complete Playbook

```yaml
---
- name: Demo on ios_command
  hosts: R1
  gather_facts: false

  tasks:

    - name: Send show commands
      cisco.ios.ios_command:
        commands:
          - "show ip interface brief"
          - "show ip interface brief | include FastEthernet0/0"
          - "show ip interface brief | include FastEthernet2/0"

        match: any

        wait_for:
          - result[1] contains up
          - result[2] contains up

        interval: 10
        retries: 10

      register: show_commands

    - name: Display output
      ansible.builtin.debug:
        var: show_commands
```

```yaml

```

contains

Only one condition must be true.

If `match` were `all`, then **both** conditions would need to be true for the task to succeed.

## Step 7

```yaml

retries: 10
```

Retry logic:

```
Attempt 1
      ↓
Condition failed?
      ↓
Wait 10 sec
      ↓
Attempt 2
      ↓
Wait 10 sec
      ↓
Attempt 3
      ↓
...
      ↓
Attempt 10
```

If the condition is never met after 10 attempts, the task fails.

# Understanding the Output

Your registered variable will look similar to:

```yaml
stdout:
  - Full output of show ip interface brief
  - FastEthernet0/0 192.168.90.11 YES NVRAM up up
  - FastEthernet2/0 192.168.91.11 YES manual up up
```

Notice that **each command has its own output**. This is why you see the `FastEthernet0/0` and `FastEthernet2/0` lines separately—they are the results of the second and third commands, not duplicates of the first command.

Similarly,

```yaml
stdout_lines:
  -
    - Interface ...
    - FastEthernet0/0 ...
    - FastEthernet2/0 ...
  -
    - FastEthernet0/0 ...
  -
    - FastEthernet2/0 ...
```

`stdout_lines` is simply the line-by-line version of `stdout`, where each command's output is represented as a list of lines.

---

# Key Points to Remember

- `ios_command` executes **show/EXEC commands** on Cisco IOS devices.
    
- Each command in the `commands` list produces a separate output.
    
- Outputs are stored in the order commands are executed (`result[0]`, `result[1]`, etc.).
    
- `wait_for` validates the command output before continuing.
    
- `match: all` requires every condition to pass (default).
    
- `match: any` requires at least one condition to pass.
    
- `interval` specifies the delay between retries.
    
- `retries` sets the maximum number of retry attempts.
    
- `register` saves the module output for later use in the playbook.


In the `cisco.ios.ios_command` module, the **`prompt`** parameter is used when a command causes the Cisco IOS device to display an **interactive prompt** and wait for user input. Since Ansible runs non-interactively, you must tell it **what prompt to expect** and **what answer to send**.

---

# Why is `prompt` Needed?

Some Cisco IOS commands don't execute immediately. Instead, they ask for confirmation, for example:

```text
R1#clear counters

Clear "show interface" counters on this interface [confirm]
```

The device is waiting for you to press **Enter**. Without handling this prompt, the Ansible task would hang or eventually time out.

The `prompt` parameter tells Ansible:

> "When you see this prompt, respond with the specified answer."

---

# Syntax

```yaml
- name: Interactive command
  cisco.ios.ios_command:
    commands:
      - command: clear counters
        prompt: '\[confirm\]'
        answer: "\r"
```

Here:

- `command` → The command to execute.
    
- `prompt` → The text (or regular expression) Ansible waits for.
    
- `answer` → The response to send.
    

---

# Example 1: Press Enter for Confirmation

On Cisco IOS:

```text
R1#clear counters

Clear "show interface" counters on this interface [confirm]
```

Normally, you press **Enter**.

In Ansible:

```yaml
- name: Clear interface counters
  cisco.ios.ios_command:
    commands:
      - command: clear counters
        prompt: '\[confirm\]'
        answer: "\r"
```

Explanation:

- `prompt` matches `[confirm]`.
    
- `answer: "\r"` sends a carriage return (equivalent to pressing Enter).
    

---

# Example 2: Answering Yes/No Prompts

Suppose a command asks:

```text
Delete filename [startup-config]?
```

You want to answer `yes`.

```yaml
- name: Delete startup config
  cisco.ios.ios_command:
    commands:
      - command: delete startup-config
        prompt: '\?'
        answer: "yes"
```

When the `?` prompt appears, Ansible sends:

```text
yes
```

---

# Example 3: Multiple Interactive Prompts

Some commands ask more than one question.

Example:

```text
Destination filename [backup.cfg]?
```

```yaml
- name: Copy running config
  cisco.ios.ios_command:
    commands:
      - command: copy running-config flash:
        prompt: "Destination filename"
        answer: "\r"
```

Since the default filename is acceptable, pressing Enter (`"\r"`) accepts it.

---

# How `prompt` Works

When you define:

```yaml
commands:
  - command: clear counters
    prompt: '\[confirm\]'
    answer: "\r"
```

The sequence is:

```text
Ansible
   │
   │ clear counters
   ▼
Router

Clear "show interface" counters [confirm]

   ▲
   │ prompt matched
   │
Ansible sends Enter (\r)

   ▼
Router executes the command
```

---

# `prompt` Uses Regular Expressions

The `prompt` value is treated as a **regular expression (regex)**. This makes it flexible enough to match varying prompt text.

Example:

```yaml
prompt: '\[confirm\]'
```

The square brackets are escaped (`\[` and `\]`) because they have special meaning in regex.

You can also match plain text:

```yaml
prompt: "Destination filename"
```

---

# Common Prompt and Answer Values

|Cisco Prompt|`prompt`|`answer`|
|---|---|---|
|`[confirm]`|`'\[confirm\]'`|`"\r"`|
|`Proceed?`|`"Proceed"`|`"yes"`|
|`Destination filename`|`"Destination filename"`|`"\r"`|
|`Password:`|`"Password:"`|`"MyPassword"`|

---

# Difference Between `commands` as Strings and Dictionaries

Simple command:

```yaml
commands:
  - show version
```

Interactive command:

```yaml
commands:
  - command: clear counters
    prompt: '\[confirm\]'
    answer: "\r"
```

Use the dictionary form (`command`, `prompt`, `answer`) whenever a command requires interaction.

---

# Key Points to Remember

- `prompt` is used for **interactive Cisco IOS commands** that pause and wait for user input.
    
- It specifies the text or regular expression Ansible should look for before responding.
    
- `answer` is the response Ansible sends when the prompt is detected.
    
- `answer: "\r"` is commonly used to simulate pressing the **Enter** key.
    
- `prompt` is **not needed** for normal `show` commands because they do not require interactive input.
