# Ansible Cisco IOS Resource Modules: `ios_interfaces`, `ios_l2_interfaces`, and `ios_l3_interfaces`

## 📌 Overview

The Cisco IOS Ansible collection provides **resource modules** for managing interface configurations. Instead of sending individual CLI commands, these modules use **structured YAML data**, making playbooks easier to read, maintain, and reuse.

The three most commonly used interface resource modules are:

|Module|Purpose|
|---|---|
|`cisco.ios.ios_interfaces`|Manage general interface properties (description, shutdown state, MTU, speed, duplex, etc.).|
|`cisco.ios.ios_l2_interfaces`|Manage Layer 2 interface settings (access mode, trunk mode, VLANs).|
|`cisco.ios.ios_l3_interfaces`|Manage Layer 3 interface settings (IP addresses and related Layer 3 configuration).|

---

# Understanding the Difference

Think of an interface as having three layers of configuration.

```text
+--------------------------------------+
| General Interface Configuration      |
| (description, admin state, mtu)      |
+--------------------------------------+
| Layer 2 Configuration                |
| (switchport mode, VLANs, trunks)     |
+--------------------------------------+
| Layer 3 Configuration                |
| (IP address, subnet mask)            |
+--------------------------------------+
```

Each module manages a different portion of the interface configuration.

---

# 1. `cisco.ios.ios_interfaces`

## Purpose

The `ios_interfaces` module manages **general interface properties**.

Typical configurations include:

- Description
    
- Shutdown / No Shutdown
    
- MTU
    
- Speed
    
- Duplex
    
- Interface enable/disable
    

---

## Cisco CLI Example

```text
interface GigabitEthernet0/0
 description Connected to ISP
 no shutdown
 mtu 1500
 speed auto
 duplex auto
```

---

## Equivalent Ansible

```yaml
- name: Configure interface
  cisco.ios.ios_interfaces:
    config:
      - name: GigabitEthernet0/0
        description: Connected to ISP
        enabled: true
        mtu: 1500
    state: merged
```

---

## Common Parameters

|Parameter|Description|
|---|---|
|`name`|Interface name.|
|`description`|Interface description.|
|`enabled`|`true` = `no shutdown`, `false` = `shutdown`.|
|`mtu`|Configure interface MTU.|
|`speed`|Interface speed.|
|`duplex`|Duplex mode.|

---

# 2. `cisco.ios.ios_l2_interfaces`

## Purpose

The `ios_l2_interfaces` module manages **Layer 2 switchport configuration**.

It is used only on interfaces operating as **switchports**.

Typical configurations include:

- Access mode
    
- Trunk mode
    
- Native VLAN
    
- Allowed VLANs
    
- Access VLAN
    

---

## Cisco CLI Example

### Access Port

```text
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10
```

---

### Trunk Port

```text
interface GigabitEthernet0/2
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30
```

---

## Equivalent Ansible

### Access Port

```yaml
- name: Configure access port
  cisco.ios.ios_l2_interfaces:
    config:
      - name: GigabitEthernet0/1
        mode: access
        access:
          vlan: 10
    state: merged
```

---

### Trunk Port

```yaml
- name: Configure trunk
  cisco.ios.ios_l2_interfaces:
    config:
      - name: GigabitEthernet0/2
        mode: trunk
        trunk:
          native_vlan: 99
          allowed_vlans:
            - 10
            - 20
            - 30
    state: merged
```

---

## Common Parameters

|Parameter|Description|
|---|---|
|`mode`|Access or trunk mode.|
|`access.vlan`|Configure access VLAN.|
|`trunk.native_vlan`|Configure native VLAN.|
|`trunk.allowed_vlans`|Configure allowed VLAN list.|

---

# 3. `cisco.ios.ios_l3_interfaces`

## Purpose

The `ios_l3_interfaces` module manages **Layer 3 interface configuration**, primarily IP addressing.

Typical configurations include:

- IPv4 address
    
- IPv6 address
    
- Secondary IP addresses
    

---

## Cisco CLI Example

```text
interface GigabitEthernet0/0
 ip address 192.168.10.1 255.255.255.0
```

---

## Equivalent Ansible

```yaml
- name: Configure IP address
  cisco.ios.ios_l3_interfaces:
    config:
      - name: GigabitEthernet0/0
        ipv4:
          - address: 192.168.10.1/24
    state: merged
```

---

## Multiple IP Addresses

```yaml
- name: Configure multiple IP addresses
  cisco.ios.ios_l3_interfaces:
    config:
      - name: GigabitEthernet0/0
        ipv4:
          - address: 192.168.10.1/24
          - address: 10.10.10.1/24
            secondary: true
    state: merged
```

---

## Common Parameters

|Parameter|Description|
|---|---|
|`name`|Interface name.|
|`ipv4.address`|IPv4 address in CIDR notation.|
|`secondary`|Configure a secondary IP address.|
|`ipv6.address`|IPv6 address.|

---

# Comparison of the Three Modules

|Feature|`ios_interfaces`|`ios_l2_interfaces`|`ios_l3_interfaces`|
|---|---|---|---|
|Description|✅|❌|❌|
|Shutdown / No Shutdown|✅|❌|❌|
|MTU|✅|❌|❌|
|Speed / Duplex|✅|❌|❌|
|Access VLAN|❌|✅|❌|
|Trunk Mode|❌|✅|❌|
|Native VLAN|❌|✅|❌|
|Allowed VLANs|❌|✅|❌|
|IPv4 Address|❌|❌|✅|
|IPv6 Address|❌|❌|✅|

---

# When to Use Each Module

## Use `ios_interfaces`

When configuring general interface properties.

Examples:

- Interface description
    
- Shutdown / No Shutdown
    
- MTU
    
- Speed
    
- Duplex
    

---

## Use `ios_l2_interfaces`

When configuring switchport settings.

Examples:

- Access VLAN
    
- Trunk VLANs
    
- Native VLAN
    
- Switchport mode
    

---

## Use `ios_l3_interfaces`

When configuring routing interfaces.

Examples:

- Router interfaces
    
- SVIs (VLAN interfaces)
    
- Routed switch ports
    
- Loopback interfaces
    

---

# Example Deployment

Suppose you want to configure the following interface:

```text
interface GigabitEthernet0/1
 description User PC
 switchport mode access
 switchport access vlan 20
 no shutdown
```

You would use:

### Step 1 – Configure General Interface

```yaml
cisco.ios.ios_interfaces:
  config:
    - name: GigabitEthernet0/1
      description: User PC
      enabled: true
```

---

### Step 2 – Configure Layer 2

```yaml
cisco.ios.ios_l2_interfaces:
  config:
    - name: GigabitEthernet0/1
      mode: access
      access:
        vlan: 20
```

---

If the interface is a routed port:

```text
interface GigabitEthernet0/0
 description WAN Link
 ip address 172.16.1.1 255.255.255.252
 no shutdown
```

You would use:

### Step 1 – General Interface Settings

```yaml
cisco.ios.ios_interfaces:
  config:
    - name: GigabitEthernet0/0
      description: WAN Link
      enabled: true
```

---

### Step 2 – Layer 3 Configuration

```yaml
cisco.ios.ios_l3_interfaces:
  config:
    - name: GigabitEthernet0/0
      ipv4:
        - address: 172.16.1.1/30
```

---

# Best Practices

- Use **`ios_interfaces`** for common interface settings.
    
- Use **`ios_l2_interfaces`** only for Layer 2 switchport configuration.
    
- Use **`ios_l3_interfaces`** only for IP addressing and Layer 3 settings.
    
- Combine these modules in the same playbook when an interface requires both general and Layer-specific configuration.
    
- Prefer resource modules over `ios_config` for structured, idempotent, and easier-to-maintain automation.
    

---

# Key Takeaways

|Module|Remember It As|
|---|---|
|`ios_interfaces`|General interface properties|
|`ios_l2_interfaces`|Switchport (Layer 2) configuration|
|`ios_l3_interfaces`|IP addressing (Layer 3) configuration|

---

# Summary

Cisco IOS resource modules divide interface management into logical components:

- **`ios_interfaces`** manages general interface settings such as descriptions and administrative state.
    
- **`ios_l2_interfaces`** manages Layer 2 switchport features like VLANs and trunking.
    
- **`ios_l3_interfaces`** manages Layer 3 addressing, including IPv4 and IPv6 configuration.
    

Using these specialized modules results in cleaner playbooks, better idempotency, and easier management of network device configurations.
