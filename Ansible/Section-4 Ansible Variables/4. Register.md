# Ansible `register` Notes

## What is `register`?

`register` is used to **store the output of a task in a variable**. You can use that variable in later tasks for:

- Displaying output
    
- Making decisions (`when`)
    
- Running loops
    
- Saving command results
    
- Checking if a task changed or failed
    

---

## Syntax

```yaml
- name: Run a command
  module_name:
    option: value
  register: variable_name
```

- `register` is written at the **same indentation level** as the module name.
    
- The variable exists only during the current playbook run.
    

---

## Example (Cisco IOS)

```yaml
- name: Running show Commands in Cisco IOS
  hosts: R1
  gather_facts: false

  tasks:
    - name: Run show version command
      cisco.ios.ios_command:
        commands:
          - show version
      register: cisco_ios_command

    - name: Display show version output
      ansible.builtin.debug:
        msg: "{{ cisco_ios_command.stdout }}"
```

### Explanation

Task 1

```yaml
register: cisco_ios_command
```

Stores the output of `show version` into the variable `cisco_ios_command`.

Task 2

```yaml
msg: "{{ cisco_ios_command.stdout }}"
```

Displays the command output that was stored.

---

# What does `register` store?

`register` stores much more than just the command output.

Example:

```yaml
- name: Run show version
  cisco.ios.ios_command:
    commands:
      - show version
  register: result
```

The variable `result` contains data similar to:

```yaml
result:
  changed: false
  failed: false
  stdout:
    - Cisco IOS XE Software, Version 17.09.01
  stdout_lines:
    - - Cisco IOS XE Software
      - Version 17.09.01
  warnings: []
```

---

## Common fields

|Field|Description|
|---|---|
|`stdout`|Output of the command as a list|
|`stdout_lines`|Output split into individual lines|
|`changed`|Whether the task changed anything|
|`failed`|Whether the task failed|
|`rc`|Return code (for shell/command modules)|
|`msg`|Error or status message|

---

# Accessing registered variables

## Display full output

```yaml
- debug:
    var: result
```

Output:

```yaml
ok: [R1] =>
  result:
    changed: false
    stdout:
      - Cisco IOS XE Software...
```

---

## Display only stdout

```yaml
- debug:
    msg: "{{ result.stdout }}"
```

Output

```text
[
  "Cisco IOS XE Software..."
]
```

---

## Display first command output

Since `stdout` is a list:

```yaml
- debug:
    msg: "{{ result.stdout[0] }}"
```

Output

```text
Cisco IOS XE Software...
```

---

## Display line by line

```yaml
- debug:
    msg: "{{ result.stdout_lines }}"
```

Example Output

```text
Cisco IOS XE Software
Version 17.09.01
Compiled Thu...
```

# Example 2: Multiple commands

```yaml
- name: Run multiple commands
  cisco.ios.ios_command:
    commands:
      - show version
      - show ip interface brief
  register: output
```

Output structure

```yaml
stdout:
  - Cisco IOS XE Software...
  - Interface IP-Address OK? Method Status
```

Display the second command output

```yaml
- debug:
    msg: "{{ output.stdout[1] }}"
```

---

# Example 3: Using `register` with `when`

```yaml
- name: Show version
  cisco.ios.ios_command:
    commands:
      - show version
  register: version

- name: Display message
  debug:
    msg: "IOS XE Device"
  when: "'IOS XE' in version.stdout[0]"
```

The second task runs only if the output contains `IOS XE`.

---

# Example 4: Register with Linux command

```yaml
- name: Check hostname
  command: hostname
  register: hostname_output

- debug:
    msg: "{{ hostname_output.stdout }}"
```

Output

```text
server01
```

# Example 5: Register and check success

```yaml
- name: Ping router
  command: ping -c 1 192.168.1.1
  register: ping_result

- debug:
    msg: "Ping Successful"
  when: ping_result.rc == 0
```

# Example 6: Display the complete registered variable

```yaml
- name: Show version
  cisco.ios.ios_command:
    commands:
      - show version
  register: version

- name: Display everything
  debug:
    var: version
```

This is useful when learning because it lets you see every field stored by `register`.

---

# Best Practices

- Use meaningful variable names.
    
    ```yaml
    register: show_version
    ```
    
    Instead of:
    
    ```yaml
    register: output
    ```
    
- Use `debug: var=` to inspect the structure of a registered variable before accessing its fields.
    
- Use `stdout[0]` when a module returns the output as a list for a single command.
    
- Use `stdout_lines` if you want to process the output line by line.
    

---

# Summary

|Syntax|Purpose|
|---|---|
|`register: result`|Stores task output in a variable|
|`result.stdout`|Displays the command output|
|`result.stdout[0]`|Displays the first command's output|
|`result.stdout_lines`|Displays output split into lines|
|`result.changed`|Indicates whether the task made changes|
|`result.failed`|Indicates whether the task failed|
|`result.rc`|Return code (mainly for `command`/`shell` modules)|
|`debug: var=result`|Displays the entire registered variable|

## Remember

Think of `register` as **capturing the output of one task so that later tasks can reuse it**. This is especially useful for:

- Showing command output
    
- Making decisions with `when`
    
- Validating device state
    
- Using command results in later tasks
    
- Troubleshooting by inspecting module return values
