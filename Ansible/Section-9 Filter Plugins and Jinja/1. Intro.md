# Ansible Filters Demo

## Overview

This playbook demonstrates several commonly used **Jinja2 filters** in Ansible. Filters are used to transform, format, or manipulate data before it is displayed or passed to a module.

---

# Playbook

```yaml
---
- name: Demo on Filters
  hosts: ciscoIOS
  gather_facts: false

  vars:
    local_usernames:
      - admin
      - operator

    local_usernames_dict:
      admin: devnet
      operator: devnet

    local_usernames_list:
      - usr: admin
        pwd: admin123
      - usr: operator
        pwd: operator123

  tasks:
    - name: Filters Demo
      ansible.builtin.debug:
        msg:
          - "{{ inventory_hostname | lower }}"
          - "{{ device_role | default('networK_device') }}"
          - "{{ device_role | default(omit) }}"
          - "{{ local_usernames | type_debug }}"
          - "{{ local_usernames_list | type_debug }}"
          - "{{ local_usernames_dict | type_debug }}"
          - "{{ local_usernames_dict | dict2items }}"
          - "{{ local_usernames_list | items2dict(key_name='usr', value_name='pwd') }}"

    - name: Display the variables
      ansible.builtin.debug:
        msg:
          - "{{ local_usernames }}"
          - "{{ local_usernames_list }}"
          - "{{ local_usernames_dict }}"
...
```

# Filters Explained

## 1. lower

```jinja
{{ inventory_hostname | lower }}
```

### Purpose

Converts a string to lowercase.

### Example

If

```yaml
inventory_hostname: R1
```

Output

```text
r1
```

Another example

```yaml
CORE-SW1
```

becomes

```text
core-sw1
```

### When to use

- Standardize hostnames
- Case-insensitive comparisons
- Generate filenames or URLs

---

## 2. default

```jinja
{{ device_role | default('network_device') }}
```

### Purpose

Provides a default value if the variable is undefined.

If

```yaml
device_role: access_switch
```

Output

```text
access_switch
```

If variable does not exist

Output

```text
network_device
```

### Why use it?

Prevents playbook failures due to missing variables.

---

## 3. default(omit)

```jinja
{{ device_role | default(omit) }}
```

### Purpose

Instead of providing a default value, **omit** removes the parameter entirely.

Example

Without omit

```yaml
ios_user:
  role: ""
```

With omit

```yaml
ios_user:
```

The parameter is not sent to the module.

### When useful

Optional module parameters.

For example

```yaml
ios_user:
  name: admin
  privilege: "{{ privilege | default(omit) }}"
```

If `privilege` doesn't exist, the module never receives that parameter.

---

## 4. type_debug

```jinja
{{ local_usernames | type_debug }}
```

### Purpose

Displays the data type of a variable.

Examples

```yaml
local_usernames
```

Output

```text
list
```

---

```yaml
local_usernames_dict
```

Output

```text
dict
```

---

```yaml
inventory_hostname
```

Output

```text
str
```

### Why use it?

Very useful while debugging variables.

---

## 5. dict2items

```jinja
{{ local_usernames_dict | dict2items }}
```

### Purpose

Converts a dictionary into a list of dictionaries.

Input

```yaml
admin: devnet
operator: devnet
```

Output

```yaml
- key: admin
  value: devnet

- key: operator
  value: devnet
```

### Why?

Loops work better with lists than dictionaries.

Example

```yaml
- debug:
    msg: "{{ item.key }} -> {{ item.value }}"
  loop: "{{ local_usernames_dict | dict2items }}"
```

Output

```text
admin -> devnet
operator -> devnet
```

---

## 6. items2dict

```jinja
{{ local_usernames_list | items2dict(key_name='usr', value_name='pwd') }}
```

### Purpose

Converts a list of dictionaries into a single dictionary.

Input

```yaml
- usr: admin
  pwd: admin123

- usr: operator
  pwd: operator123
```

Output

```yaml
admin: admin123
operator: operator123
```

### Explanation

The filter needs to know which field should become:

- dictionary key
- dictionary value

So we specify

```yaml
key_name='usr'
value_name='pwd'
```

Meaning

```
usr  -> key
pwd  -> value
```

# Summary Table

| Filter | Input | Output | Purpose |
|---------|-------|--------|---------|
| `lower` | `"R1"` | `"r1"` | Convert string to lowercase |
| `default()` | Undefined variable | Default value | Prevent undefined variable errors |
| `default(omit)` | Undefined variable | Parameter omitted | Skip optional module arguments |
| `type_debug` | Any variable | `list`, `dict`, `str` | Show variable type |
| `dict2items` | Dictionary | List of key/value dictionaries | Easier looping |
| `items2dict` | List of dictionaries | Dictionary | Reverse of `dict2items` |

---

# Key Takeaways

- `lower` normalizes string case.
- `default` supplies fallback values for undefined variables.
- `default(omit)` completely removes optional parameters.
- `type_debug` helps identify variable data types during troubleshooting.
- `dict2items` transforms dictionaries into loop-friendly lists.
- `items2dict` reconstructs dictionaries from structured lists.

These filters are among the most commonly used Jinja2 filters in Ansible automation and are particularly useful when processing inventory data, API responses, and structured configuration variables.
