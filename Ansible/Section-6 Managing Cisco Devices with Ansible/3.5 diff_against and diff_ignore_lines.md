# Ansible: `diff_against` and `diff_ignore_lines` (Cisco IOS)

## 📌 Overview

The `diff_against` parameter in the `cisco.ios.ios_config` module compares the device configuration with another configuration and displays the differences (**diff**).

The `diff_ignore_lines` parameter allows you to exclude specific lines from the comparison. This is useful for ignoring dynamic configuration entries that change frequently, such as timestamps or clock settings.

---

# Playbook

```yaml
---
- name: Demo on diff
  hosts: R1
  gather_facts: false

  tasks:
    - name: Demo on diff_against
      cisco.ios.ios_config:
        lines:
          - description connected to the PC1
        parents:
          - interface FastEthernet0/0

        diff_against: intended

        intended_config: "{{ lookup('file', playbook_dir + '/intended_config/' + inventory_hostname + '_goldenconfig.txt') }}"

        diff_ignore_lines:
          - clock *

      register: output

    - name: Result
      ansible.builtin.debug:
        msg: "{{ output }}"
```

# `diff_against`

## Purpose

`diff_against` compares the device configuration with another configuration and displays the differences.

It is commonly used for:

- Configuration validation
    
- Compliance checking
    
- Auditing
    
- Identifying configuration drift
    

---

## Supported Values

|Value|Description|
|---|---|
|`running`|Compare the intended configuration against the current running configuration.|
|`startup`|Compare the running configuration with the startup configuration.|
|`intended`|Compare the running configuration with a user-provided configuration (golden configuration).|

---

# Using `diff_against: intended`

In this playbook:

```yaml
diff_against: intended
```

Ansible compares:

```text
Running Configuration
        │
        ▼
Golden Configuration
(intended_config)
        │
        ▼
Display Differences
```

No configuration is changed during the comparison.

Instead, Ansible checks whether the running configuration matches the expected configuration.

---

# `intended_config`

The `intended_config` parameter specifies the expected (golden) configuration.

```yaml
intended_config: "{{ lookup('file', playbook_dir + '/intended_config/' + inventory_hostname + '_goldenconfig.txt') }}"
```

---

## How It Works

The `lookup('file', ...)` function reads the contents of a local file on the Ansible control node.

Example directory:

```text
project/
│
├── playbook.yml
└── intended_config/
      ├── R1_goldenconfig.txt
      └── R2_goldenconfig.txt
```

If the current host is **R1**, Ansible reads:

```text
intended_config/R1_goldenconfig.txt
```

The entire file becomes the expected configuration for comparison.

---

# Example Golden Configuration

```text
hostname R1

interface FastEthernet0/0
 description connected to the PC1
 ip address 192.168.1.1 255.255.255.0

router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
```

# `diff_ignore_lines`

## Purpose

Some configuration lines change automatically and are not important during compliance checks.

`diff_ignore_lines` tells Ansible to ignore those lines when generating the diff.

Example:

```yaml
diff_ignore_lines:
  - clock *
```

---

# Why Ignore Lines?

Cisco devices automatically update certain configuration entries, such as:

```text
clock timezone EST 5 30
clock summer-time EDT recurring
clock period 123456789
```

These values may change over time even though the device is correctly configured.

Ignoring them prevents unnecessary differences from appearing in the output.

---

# Pattern Matching

`diff_ignore_lines` supports simple wildcard patterns.

Example:

```yaml
diff_ignore_lines:
  - clock *
```

This ignores every configuration line that begins with:

```text
clock
```

Examples ignored:

```text
clock timezone EST 5 30
clock summer-time EDT recurring
clock period 123456
```

---

# Multiple Ignore Rules

You can ignore multiple configuration patterns.

```yaml
diff_ignore_lines:
  - clock *
  - ntp clock-period *
  - service timestamps *
```

This keeps the diff focused on meaningful configuration differences.

# Advantages of `diff_against`

- Detects configuration drift.
    
- Validates devices against a golden configuration.
    
- Supports compliance auditing.
    
- Helps verify network standardization.
    
- Shows exactly which lines differ.
    

---

# Advantages of `diff_ignore_lines`

- Removes unnecessary differences.
    
- Ignores dynamic configuration entries.
    
- Produces cleaner and more readable diff output.
    
- Focuses attention on important configuration changes.
    

---

# Key Points

|Parameter|Purpose|
|---|---|
|`diff_against`|Compares configurations and displays differences.|
|`running`|Compares the intended changes against the running configuration.|
|`startup`|Compares the running configuration with the startup configuration.|
|`intended`|Compares the running configuration with a user-defined golden configuration.|
|`intended_config`|Specifies the expected configuration used for comparison.|
|`lookup('file', ...)`|Reads the golden configuration file from the Ansible control node.|
|`diff_ignore_lines`|Excludes matching configuration lines from the diff output.|
|`clock *`|Ignores all configuration lines beginning with `clock`.|

---

# Expected Result

When this playbook runs:

1. Ansible connects to the Cisco IOS device.
    
2. It reads the golden configuration from the `intended_config` directory.
    
3. It downloads the device's running configuration.
    
4. Any lines matching `clock *` are ignored.
    
5. The running configuration is compared with the golden configuration.
    
6. Any differences are displayed in the task output.
    
7. The comparison result is stored in the `output` variable for further processing or debugging.
