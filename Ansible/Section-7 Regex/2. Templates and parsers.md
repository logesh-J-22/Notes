# Ansible CLI Output Parsing: TextFSM, NTC Template Parser, and pyATS Parser

## 📌 Overview

Network devices usually return command output as **unstructured text**.

Example Cisco IOS output:

```text
R1# show ip interface brief

Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     192.168.1.1     YES manual up                    up
GigabitEthernet0/1     unassigned      YES unset  administratively down down
Loopback0              10.10.10.1      YES manual up                    up
```

While this output is easy for humans to read, it is difficult for automation tools to process.

Parsers convert CLI text into **structured data** such as:

- JSON
    
- YAML dictionaries
    
- Lists
    
- Key-value pairs
    

Ansible provides the `ansible.utils.cli_parse` module to parse command output.

---

# `ansible.utils.cli_parse`

## Purpose

The `ansible.utils.cli_parse` module:

- Executes a command on a network device.
    
- Parses the output using a selected parser.
    
- Converts text output into structured data.
    
- Stores the result as an Ansible fact.
    

Syntax:

```yaml
ansible.utils.cli_parse:
  command: <show command>

  parser:
    name: <parser_name>

  set_fact: <variable_name>
```

---

# Supported Parsers

Common parsers used in Ansible network automation:

|Parser|Description|
|---|---|
|TextFSM|Template-based parser using regular expressions.|
|NTC Templates|Community-maintained TextFSM templates.|
|pyATS|Cisco-developed structured parser framework.|

# 1. TextFSM Parser

## 📌 Overview

**TextFSM (Text Template State Machine)** is a Python-based parsing library created by Google.

It uses templates containing:

- Regular expressions
    
- Variables
    
- State definitions
    

to convert CLI output into structured data.

---

# TextFSM Workflow

```text
CLI Output
    |
    |
    ▼
TextFSM Template
(Regex Rules)
    |
    ▼
Structured Data
```

---

# Installation

Install TextFSM:

```bash
pip install textfsm
```

Install Ansible collection:

```bash
ansible-galaxy collection install ansible.utils
```

---

# TextFSM Template Example

File:

```text
templates/fetch_show_interface.textfsm
```

Example:

```text
Value INTERFACE (\S+)
Value IP (\S+)
Value STATUS (\S+)
Value PROTOCOL (\S+)

Start

  ^${INTERFACE}\s+${IP}\s+\S+\s+\S+\s+${STATUS}\s+${PROTOCOL} -> Record
```

---

# TextFSM Playbook Example

```yaml
---
- name: Demo on TextFSM
  hosts: R1
  gather_facts: false

  tasks:

    - name: TextFSM CLI parser
      ansible.utils.cli_parse:

        command: show ip interface brief

        parser:
          name: ansible.utils.textfsm

          template_path:
            "{{ playbook_dir }}/templates/fetch_show_interface.textfsm"

        set_fact: output


    - name: Display output
      ansible.builtin.debug:
        msg: "{{ output }}"
```

---

# TextFSM Output Example

Input:

```text
GigabitEthernet0/0 192.168.1.1 YES manual up up
Loopback0 10.10.10.1 YES manual up up
```

Output:

```yaml
output:
  - INTERFACE: GigabitEthernet0/0
    IP: 192.168.1.1
    STATUS: up
    PROTOCOL: up

  - INTERFACE: Loopback0
    IP: 10.10.10.1
    STATUS: up
    PROTOCOL: up
```

---

# Advantages of TextFSM

✅ Simple regex-based parsing  
✅ Works with any vendor CLI output  
✅ Custom templates can be created  
✅ Lightweight and fast

---

# Limitations of TextFSM

❌ Requires writing templates manually  
❌ Regex knowledge required  
❌ Different commands require different templates

# 2. NTC Template Parser

## 📌 Overview

**NTC Templates (Network to Code Templates)** are a collection of pre-built TextFSM templates.

Instead of creating your own template, you can use community-maintained templates.

Examples:

```text
show version
show interfaces
show ip interface brief
show vlan
show inventory
```

---

# Installation

Install ntc-templates:

```bash
pip install ntc-templates
```

Set environment variable:

```bash
export NET_TEXTFSM=/path/to/ntc-templates/templates
```

---

# How NTC Templates Work

```text
Cisco Command
      |
      ▼
NTC Template Library
      |
      ▼
TextFSM Engine
      |
      ▼
Structured Output
```

---

# Example

Command:

```text
show ip interface brief
```

NTC template:

```text
cisco_ios_show_ip_interface_brief.textfsm
```

Output:

```yaml
interfaces:
  - interface: GigabitEthernet0/0
    ip_address: 192.168.1.1
    status: up
    protocol: up
```

---

# Using NTC Templates in Ansible

Example:

```yaml
---
- name: Parse Cisco output using NTC
  hosts: R1
  gather_facts: false

  tasks:

    - name: Parse command
      ansible.utils.cli_parse:

        command: show ip interface brief

        parser:
          name: ansible.utils.ntc_templates

        set_fact: output


    - name: Display result
      debug:
        var: output
```

---

# Advantages of NTC Templates

✅ Large collection of ready-made templates  
✅ Supports many vendors  
✅ No need to write regex manually  
✅ Community maintained

---

# Limitations of NTC Templates

❌ Depends on available templates  
❌ Output changes may break templates  
❌ Requires template package installation

# 3. pyATS Parser

## 📌 Overview

**pyATS (Python Automated Test System)** is a Cisco-developed automation framework.

The Genie parser library inside pyATS can automatically parse Cisco command output into structured data.

It supports many Cisco platforms:

- IOS
    
- IOS-XE
    
- NX-OS
    
- ASA
    

---

# pyATS Workflow

```text
Cisco Device
      |
      ▼
Show Command
      |
      ▼
Genie Parser
      |
      ▼
Structured Dictionary
```

---

# Installation

Install pyATS:

```bash
pip install pyats
```

Install Genie:

```bash
pip install genie
```

---

# pyATS Ansible Example

```yaml
---
- name: Demo on pyATS parser
  hosts: R1
  gather_facts: false

  tasks:

    - name: pyATS template parser
      ansible.utils.cli_parse:

        command: show version

        parser:
          command: show version
          name: ansible.netcommon.pyats

        set_fact: output


    - name: Display output
      ansible.builtin.debug:
        msg: "{{ output }}"
```

---

# Advantages of pyATS

✅ Ideal for Cisco environments

---

# Limitations of pyATS

❌ Mainly focused on Cisco devices  
❌ Requires pyATS installation  
❌ Some commands may not have parsers

# When to Use Which Parser?

## Use TextFSM When:

- No existing template exists.
    
- You need custom parsing.
    
- You understand regex.
    

Example:

```text
Custom show command
```

---

## Use NTC Templates When:

- A template already exists.
    
- You need multi-vendor support.
    
- You want quick results.
    

Example:

```text
show vlan
show interfaces
```

---

## Use pyATS When:

- Working mainly with Cisco devices.
    
- You need detailed structured output.
    
- You want Cisco-supported parsing.
    

Example:

```text
show version
show interface
show ip route
```

# Summary

CLI parsers allow Ansible to convert raw network device output into structured data.

- **TextFSM** provides flexibility by allowing custom regex templates.
    
- **NTC Templates** provide ready-made TextFSM templates for common commands.
    
- **pyATS** provides Cisco-developed parsers with rich structured output.
    

Using `ansible.utils.cli_parse` with these parsers enables powerful automation tasks such as:

- Configuration validation
    
- Inventory collection
    
- Compliance checking
    
- Network monitoring
    
- Automated troubleshooting
