Used for repeating tasks with the set of items 

# Ansible Notes: `loop`, `with_items`, `with_list`, and `with_dict`

## 1. Introduction

Ansible provides multiple ways to iterate over data structures such as lists and dictionaries.

Older playbooks use the **with_*** family of loops (`with_items`, `with_dict`, `with_list`, etc.), while modern Ansible recommends using **`loop`** because it provides a consistent syntax and works well with filters.

> **Recommendation:** Prefer **`loop`** for new playbooks. Use filters such as `flatten` and `dict2items` whenever necessary.

---

# 2. loop vs with_items

## Sample Variable

```yaml
vars:
  local_usernames:
    - admin
    - operator
    - [admin_ro, operator_ro, [super_admin_ro, super_admin_rw]]
```

This variable contains

- Two strings
    
- One nested list
    

---

## Using with_items

```yaml
- name: Printing username using with_items
  ansible.builtin.debug:
    msg: "{{ item }}"
  with_items: "{{ local_usernames }}"
```

### Output

```
admin
operator
admin_ro
operator_ro
[super_admin_ro, super_admin_rw]
```

### Explanation

`with_items`

- Automatically flattens **one level**
    
- Behaves as if `flatten(1)` is applied
    

Visualization

```
Original

[
  admin,
  operator,
  [
    admin_ro,
    operator_ro,
    [
      super_admin_ro,
      super_admin_rw
    ]
  ]
]

↓

with_items

admin
operator
admin_ro
operator_ro
[super_admin_ro, super_admin_rw]
```

Notice that the innermost list is still a list.

---

## Using loop

```yaml
- name: Printing username using loop
  ansible.builtin.debug:
    msg: "{{ item }}"
  loop: "{{ local_usernames }}"
```

### Output

```
admin
operator
[admin_ro, operator_ro, [super_admin_ro, super_admin_rw]]
```

### Explanation

Unlike `with_items`, **loop preserves the original data structure**.

Nothing is flattened automatically.

Visualization

```
Original

[
  admin,
  operator,
  [
    admin_ro,
    operator_ro,
    [
      super_admin_ro,
      super_admin_rw
    ]
  ]
]

↓

loop

admin
operator
[admin_ro, operator_ro, [super_admin_ro, super_admin_rw]]
```

# 3. Flattening using loop

Since `loop` does not flatten automatically, Ansible provides the `flatten()` filter.

---

## Flatten one level

```yaml
loop: "{{ local_usernames | flatten(1) }}"
```

Output

```
admin
operator
admin_ro
operator_ro
[super_admin_ro, super_admin_rw]
```

Equivalent to

```
with_items
```

---

## Flatten two levels

```yaml
loop: "{{ local_usernames | flatten(2) }}"
```

Output

```
admin
operator
admin_ro
operator_ro
super_admin_ro
super_admin_rw
```

Everything is flattened.

Visualization

```
Original

[
 admin,
 operator,
 [
   admin_ro,
   operator_ro,
   [
      super_admin_ro,
      super_admin_rw
   ]
 ]
]

flatten(1)

admin
operator
admin_ro
operator_ro
[super_admin_ro, super_admin_rw]

flatten(2)

admin
operator
admin_ro
operator_ro
super_admin_ro
super_admin_rw
```

# 4. Looping over manually created lists

Example

```yaml
loop:
  - admin_with_items
  - operator_with_items
  - superadmin_with_items
```

Output

```
admin_with_items
operator_with_items
superadmin_with_items
```

Similarly,

```yaml
with_items:
  - admin_with_items
  - operator_with_items
  - superadmin_with_items
```

produces the same output because there are no nested lists.

# 5. Looping over a List of Dictionaries

Variable

```yaml
local_usernames_list_dict:
  - { usr: admin, pwd: devnet }
  - { usr: operator, pwd: devnet123 }
```

Structure

```
List

├── Dictionary
│      usr → admin
│      pwd → devnet
│
└── Dictionary
       usr → operator
       pwd → devnet123
```

Loop

```yaml
- debug:
    msg: "Username {{ item.usr }} Password {{ item.pwd }}"
  loop: "{{ local_usernames_list_dict }}"
```

Output

```
Username admin Password devnet

Username operator Password devnet123
```

### Explanation

Each `item` is a dictionary.

```
Iteration 1

item

usr : admin
pwd : devnet
```

Therefore

```
item.usr
item.pwd
```

are valid.

# 6. with_dict

Suppose we have a dictionary

```yaml
local_usernames_dict:

  admin: devnet
  operator: devnet123
```

`with_dict` converts it internally into

```
[
  {
    key: admin
    value: devnet
  },
  {
    key: operator
    value: devnet123
  }
]
```

Example

```yaml
- debug:
    msg: "Username {{ item.key }} Password {{ item.value }}"
  with_dict: "{{ local_usernames_dict }}"
```

Output

```
Username admin Password devnet

Username operator Password devnet123
```

# 7. loop with dict2items

`loop` **cannot iterate over a dictionary directly**.

Instead, convert the dictionary into a list using `dict2items`.

Dictionary

```yaml
local_usernames_dict:

  admin: devnet
  operator: devnet123
```

Using

```yaml
loop: "{{ local_usernames_dict | dict2items }}"
```

Internally becomes

```
[
  {
    key: admin
    value: devnet
  },
  {
    key: operator
    value: devnet123
  }
]
```

Now `loop` iterates normally.

Example

```yaml
- debug:
    msg: "Username {{ item.key }} Password {{ item.value }}"
  loop: "{{ local_usernames_dict | dict2items }}"
```

Output

```
Username admin Password devnet

Username operator Password devnet123
```

---

# 8. Why did this fail?

This variable

```yaml
local_usernames_dict:

  - admin: devnet
  - operator: devnet123
```

is **NOT** a dictionary.

It is actually

```
List

├── Dictionary
│      admin → devnet
│
└── Dictionary
       operator → devnet123
```

Calling

```yaml
loop: "{{ local_usernames_dict | dict2items }}"
```

fails because

```
dict2items
```

expects

```
Dictionary
```

but receives

```
List
```

Error

```
dict2items requires a dictionary,
got AnsibleLazyTemplateList instead.
```

# 9. Correct ways depending on the data structure

## A. List

```yaml
users:

  - admin
  - operator
```

Use

```yaml
loop: "{{ users }}"
```

---

## B. List of dictionaries

```yaml
users:

  - usr: admin
    pwd: devnet

  - usr: operator
    pwd: devnet123
```

Use

```yaml
loop: "{{ users }}"
```

Access

```yaml
item.usr
item.pwd
```

---

## C. Dictionary

```yaml
users:

  admin: devnet
  operator: devnet123
```

Use

```yaml
loop: "{{ users | dict2items }}"
```

Access

```yaml
item.key
item.value
```

---

## D. List of dictionaries containing one key-value pair each

```yaml
users:

  - admin: devnet
  - operator: devnet123
```

Use

```yaml
loop: "{{ users | map('dict2items') | flatten }}"
```

Internally

```
[
  {admin: devnet},
  {operator: devnet123}
]

↓

map(dict2items)

[
  [
    {key: admin, value: devnet}
  ],
  [
    {key: operator, value: devnet123}
  ]
]

↓

flatten

[
  {key: admin, value: devnet},
  {key: operator, value: devnet123}
]
```

# 10. with_list

`with_list` is one of the older looping constructs. It iterates over a list and behaves similarly to `loop` for simple lists.

Example:

```yaml
- name: Using with_list
  ansible.builtin.debug:
    msg: "{{ item }}"
  with_list:
    - admin
    - operator
    - guest
```

Output:

```
admin
operator
guest
```

The equivalent modern syntax is:

```yaml
- name: Using loop
  ansible.builtin.debug:
    msg: "{{ item }}"
  loop:
    - admin
    - operator
    - guest
```

> **Note:** `with_list` is largely superseded by `loop` and is rarely used in new playbooks.

# 11. Summary Table

|Feature|`loop`|`with_items`|`with_list`|`with_dict`|
|---|---|---|---|---|
|Recommended for new playbooks|✅ Yes|❌ Legacy|❌ Legacy|❌ Legacy|
|Iterates over lists|✅|✅|✅|❌|
|Iterates over dictionaries directly|❌ (`dict2items` required)|❌|❌|✅|
|Automatically flattens nested lists|❌|✅ (one level)|❌|N/A|
|Supports filters (`flatten`, `dict2items`, etc.)|✅|Limited|Limited|N/A|
|Best use case|Modern looping|Legacy list iteration|Legacy simple lists|Legacy dictionary iteration|

## Best Practice

- ✅ Use **`loop`** for all new playbooks.
    
- ✅ Use **`flatten()`** with `loop` when you need behavior similar to `with_items`.
    
- ✅ Use **`dict2items`** to iterate over dictionaries with `loop`.
    
- ⚠️ Use `with_items`, `with_list`, and `with_dict` primarily when maintaining older playbooks or following legacy examples.
