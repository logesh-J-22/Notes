# Until in Ansible

## Overview

The `until` keyword is used to **retry a task until a specified condition becomes true**. It is useful when working with operations that may not succeed immediately, such as waiting for a service to start, an interface to come up, or a device to become reachable.

The `until` keyword is commonly used together with:

- `register` – Stores the output of a task.
    
- `retries` – Specifies the maximum number of retry attempts.
    
- `delay` – Defines the number of seconds to wait between retries.
    

---

## Syntax

```yaml
- name: Example task
  <module_name>:
    ...
  register: result
  until: <condition>
  retries: 5
  delay: 10
```

---

## Example

The following playbook checks whether the `FastEthernet0/0` interface is up. If the interface is not up, Ansible retries the command three times, waiting five seconds between each attempt.

```yaml
---
- name: Until demo
  hosts: R1
  gather_facts: false

  tasks:
    - name: Check if the interface is up
      cisco.ios.ios_command:
        commands:
          - "show ip interface brief | include FastEthernet0/0"
      register: interface
      until: "'up' in interface['stdout'][0]"
      retries: 3
      delay: 5

    - name: Display the FastEthernet0/0 interface
      ansible.builtin.debug:
        msg: "{{ interface['stdout'][0] }}"
```

---

## Explanation

### `register`

Stores the output of the `ios_command` module in a variable named `interface`.

```yaml
register: interface
```

Example output:

```yaml
interface:
  stdout:
    - "FastEthernet0/0 192.168.1.1 YES NVRAM up up"
```

---

### `until`

Evaluates the specified condition after each task execution.

```yaml
until: "'up' in interface['stdout'][0]"
```

This condition checks whether the string `up` exists in the first line of the command output.

If the condition is:

- **True** → The task succeeds immediately.
    
- **False** → The task is retried until the retry limit is reached.
    

---

### `retries`

Specifies the maximum number of retry attempts.

```yaml
retries: 3
```

In this example, Ansible attempts the task up to **three additional times** if the `until` condition is not met.

---

### `delay`

Specifies how many seconds Ansible waits before retrying the task.

```yaml
delay: 5
```

Here, Ansible waits **5 seconds** between each retry.

---

## Execution Flow

```text
Run command
      │
      ▼
Evaluate 'until' condition
      │
      ├── True ─────► Task succeeds
      │
      └── False
             │
             ▼
     Wait 5 seconds
             │
             ▼
      Retry task
             │
             ▼
Continue until condition is true
or retries are exhausted
```

---

## When to Use `until`

Use `until` when:

- Waiting for a network interface to become operational.
    
- Waiting for a router or switch to finish booting.
    
- Waiting for a service to start.
    
- Waiting for an API to return the expected response.
    
- Waiting for a file or resource to become available.
    
- Polling a device until a desired state is reached.
    

---

## Best Practices

- Always use `register` with `until`.
    
- Set a reasonable value for `retries` to avoid infinite waiting.
    
- Use an appropriate `delay` to prevent excessive polling.
    
- Make the `until` condition as specific as possible to avoid false positives.
    

---

## Key Points

- `until` repeatedly executes a task until a condition evaluates to `True`.
    
- `register` stores the task output for use in the `until` condition.
    
- `retries` controls the maximum number of retry attempts.
    
- `delay` specifies the wait time between retries.
    
- If the condition is never met, the task fails after all retries are exhausted.
