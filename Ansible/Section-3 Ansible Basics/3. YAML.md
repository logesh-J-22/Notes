
## Yaml Ain't Markup Language

YAML (short for **YAML Ain't Markup Language**) is a human-readable data serialization format. It is commonly used for configuration files because it is simple to read and write. In Ansible, YAML is the primary language used to define automation tasks, playbooks, inventory variables, and roles.

## Why Ansible uses YAML

Ansible is designed to be easy to understand. YAML allows you to describe automation in a way that resembles plain English rather than writing complex code.

For example, instead of writing procedural scripts, you define **what** you want the system to look like.

## Basic YAML Syntax

### 1. Key-value pairs

```yaml
name: John
age: 25
city: Bangalore
```

Here:

- `name`, `age`, and `city` are keys.
    
- `John`, `25`, and `Bangalore` are values.
    

---

### 2. Lists

Lists begin with a hyphen (`-`).

```yaml
fruits:
  - Apple
  - Banana
  - Mango
```

Equivalent representation:

```yaml
fruits: [Apple, Banana, Mango]
```

---

### 3. Dictionaries (Mappings)

```yaml
employee:
  name: Alice
  age: 30
  department: IT
```

---

### 4. List of dictionaries

```yaml
employees:
  - name: Alice
    age: 30

  - name: Bob
    age: 28
```

---

### 5. Boolean values

```yaml
enabled: true
disabled: false
```

---

### 6. Comments

```yaml
# This is a comment
name: Alice
```

---

## Indentation is Important

YAML uses spaces instead of braces or parentheses.

Correct:

```yaml
employee:
  name: Alice
  age: 30
```

Incorrect:

```yaml
employee:
name: Alice
age: 30
```

Use **spaces**, not tabs. A common convention is **2 spaces** per indentation level.

# How YAML is used in Ansible

Almost every Ansible file is written in YAML.

These include:

- Playbooks
    
- Inventory variables
    
- Role defaults
    
- Variable files
    
- Task files
    
- Handlers
    

---

## Example 1: Simple Playbook

```yaml
---
- name: Install Apache
  hosts: webservers
  become: yes

  tasks:
    - name: Install Apache package
      apt:
        name: apache2
        state: present
```

Explanation:

```yaml
---
```

Marks the beginning of a YAML document.

```yaml
- name: Install Apache
```

A play. The `-` indicates a list item.

```yaml
hosts: webservers
```

Specifies which hosts the play targets.

```yaml
become: yes
```

Runs tasks with elevated privileges.

```yaml
tasks:
```

Contains the list of tasks.

```yaml
- name: Install Apache package
```

Defines a task.

```yaml
apt:
  name: apache2
  state: present
```

Uses the `apt` module to ensure the `apache2` package is installed.

---

## Example 2: Variables

```yaml
---
- hosts: all

  vars:
    package_name: nginx

  tasks:
    - name: Install package
      apt:
        name: "{{ package_name }}"
        state: present
```

Here:

```yaml
package_name: nginx
```

creates a variable.

This line:

```yaml
name: "{{ package_name }}"
```

uses Jinja2 templating to substitute the variable value.

---

## Example 3: Multiple Tasks

```yaml
---
- hosts: all

  tasks:

    - name: Install nginx
      apt:
        name: nginx
        state: present

    - name: Start nginx
      service:
        name: nginx
        state: started

    - name: Enable nginx
      service:
        name: nginx
        enabled: true
```

Each task is another item in the `tasks` list.

---

## Example 4: Loops

```yaml
---
- hosts: all

  tasks:
    - name: Install packages
      apt:
        name: "{{ item }}"
        state: present
      loop:
        - git
        - curl
        - vim
```

Ansible runs the task once for each value in the `loop` list.

---

## Example 5: Conditionals

```yaml
---
- hosts: all

  tasks:
    - name: Install Apache on Ubuntu
      apt:
        name: apache2
        state: present
      when: ansible_os_family == "Debian"
```

The task runs only if the condition evaluates to `true`.

---

## Example 6: Variable File

`vars.yml`

```yaml
username: admin
password: secret123
port: 8080
```

Playbook:

```yaml
---
- hosts: all

  vars_files:
    - vars.yml

  tasks:
    - debug:
        msg: "{{ username }}"
```

Ansible loads the variables from `vars.yml` and makes them available to the playbook.

## Common YAML Data Types in Ansible

|Data Type|Example|
|---|---|
|String|`name: nginx`|
|Integer|`port: 80`|
|Boolean|`enabled: true`|
|List|`packages: [git, curl, vim]`|
|Dictionary|`user: {name: alice, uid: 1001}`|
|Null|`value: null` or `value: ~`|

## YAML Features Frequently Used in Ansible

### Variables

```yaml
server: web01
```

### Lists

```yaml
packages:
  - git
  - curl
  - vim
```

### Nested dictionaries

```yaml
database:
  host: localhost
  port: 3306
  username: admin
```

### Multiline strings

```yaml
message: |
  Welcome to the server.
  Configuration completed successfully.
```

The `|` preserves line breaks.

```yaml
message: >
  This is a very long
  sentence that becomes
  one line.
```

The `>` folds newlines into spaces.

## Best Practices

- Use **2 spaces** for indentation (avoid tabs).
    
- Give tasks descriptive `name` values.
    
- Keep playbooks modular by separating variables and tasks into different files.
    
- Use variables instead of hardcoding values.
    
- Validate your playbooks with `ansible-playbook --syntax-check` before running them.
    

## Summary

YAML is the configuration language that Ansible uses to describe infrastructure and automation. It organizes information with indentation and supports simple structures like key-value pairs, lists, and dictionaries. In Ansible, YAML is used to define:

- **Playbooks**: the sequence of automation steps.
    
- **Tasks**: individual actions, such as installing packages or starting services.
    
- **Variables**: reusable values that make playbooks flexible.
    
- **Inventories and roles**: host definitions and reusable automation components.
    

Learning YAML syntax is the first step to becoming productive with Ansible, since almost every Ansible configuration file is written in YAML.
