# Ansible Notes: Magic Variables

## What are Magic Variables?

**Magic variables** are special variables that Ansible automatically creates during playbook execution.

They provide information about:

- The current host
    
- Inventory
    
- Playbook execution
    
- Groups
    
- Variables
    
- Loops
    
- Play status
    

Unlike normal variables, **you do not define magic variables**. Ansible creates and manages them automatically.

---

# Why use Magic Variables?

Magic variables help you:

- Access inventory information
    
- Retrieve host details
    
- Reference other hosts
    
- Build dynamic playbooks
    
- Create reusable automation
    
- Make decisions based on execution context
    

---

# Common Magic Variables

|Magic Variable|Description|
|---|---|
|`hostvars`|Access variables of any host|
|`groups`|Dictionary of inventory groups|
|`group_names`|Groups the current host belongs to|
|`inventory_hostname`|Hostname from the inventory|
|`inventory_hostname_short`|Short hostname|
|`ansible_play_hosts`|Hosts still active in the play|
|`ansible_play_batch`|Hosts in the current batch|
|`play_hosts`|Alias for active hosts (older usage)|
|`ansible_check_mode`|Indicates if running in check mode|
|`ansible_diff_mode`|Indicates if running in diff mode|
|`ansible_limit`|Inventory limit used (if any)|

---

# 1. `inventory_hostname`

Returns the hostname exactly as it appears in the inventory.

Inventory

```ini
[R1]
router1 ansible_host=192.168.1.10
```

Playbook

```yaml
- hosts: R1

  tasks:
    - debug:
        msg: "{{ inventory_hostname }}"
```

Output

```
router1
```

---

# 2. `inventory_hostname_short`

Returns only the short hostname.

Example

Inventory

```ini
server01.example.com
```

Playbook

```yaml
- debug:
    msg: "{{ inventory_hostname_short }}"
```

Output

```
server01
```

---

# 3. `hostvars`

`hostvars` allows one host to access variables or facts from another host.

Syntax

```yaml
{{ hostvars['hostname'] }}
```

Example Inventory

```ini
[web]
web1 ansible_host=192.168.1.10

[db]
db1 ansible_host=192.168.1.20
```

Example

```yaml
- hosts: web

  tasks:
    - debug:
        msg: "{{ hostvars['db1'].ansible_host }}"
```

Output

```
192.168.1.20
```

---

## Access another host's facts

```yaml
- debug:
    msg: "{{ hostvars['web1'].ansible_hostname }}"
```

---

# 4. `groups`

Returns every inventory group and its members.

Inventory

```ini
[web]
web1
web2

[db]
db1
```

Playbook

```yaml
- debug:
    var: groups
```

Output

```yaml
groups:
  web:
    - web1
    - web2
  db:
    - db1
```

---

## Get all web servers

```yaml
- debug:
    msg: "{{ groups['web'] }}"
```

Output

```
["web1", "web2"]
```

---

# 5. `group_names`

Returns the groups that the current host belongs to.

Inventory

```ini
[web]
web1
```

Playbook

```yaml
- debug:
    var: group_names
```

Output

```yaml
group_names:
  - web
```

---

# 6. `ansible_play_hosts`

Returns all hosts still active in the current play.

Example

```yaml
- debug:
    var: ansible_play_hosts
```

Output

```yaml
ansible_play_hosts:
  - web1
  - web2
  - db1
```

If a host fails and is removed from the play, it no longer appears in this list.

---

# 7. `ansible_play_batch`

Returns only the hosts in the current execution batch.

Useful with:

```yaml
serial: 2
```

Example

```yaml
- hosts: web
  serial: 2

  tasks:
    - debug:
        var: ansible_play_batch
```

Suppose there are four hosts:

```
web1
web2
web3
web4
```

Output (First Batch)

```
web1
web2
```

Output (Second Batch)

```
web3
web4
```

---

# 8. `ansible_check_mode`

Indicates whether Ansible is running with:

```bash
ansible-playbook site.yml --check
```

Example

```yaml
- debug:
    msg: "Running in Check Mode"
  when: ansible_check_mode
```

---

# 9. `ansible_diff_mode`

Indicates whether playbook is running with:

```bash
ansible-playbook site.yml --diff
```

Example

```yaml
- debug:
    msg: "Diff Mode Enabled"
  when: ansible_diff_mode
```

---

# 10. `ansible_limit`

Shows the inventory limit specified when running the playbook.

Example command

```bash
ansible-playbook site.yml --limit web
```

Playbook

```yaml
- debug:
    var: ansible_limit
```

Output

```
web
```

# Example 5: Loop Through Hosts

```yaml
- hosts: localhost

  tasks:
    - name: Display all web hosts
      debug:
        msg: "{{ item }}"
      loop: "{{ groups['web'] }}"
```

Output

```
web1
web2
web3
```

Inventory

```ini
web1 location=India
web2 location=USA
```

Playbook

```yaml
- hosts: localhost

  tasks:
    - debug:
        msg: "{{ hostvars['web1'].location }}"
```

Output

```

```

# Best Practices

- Use `inventory_hostname` instead of `ansible_hostname` when you need the exact inventory name.
    
- Use `hostvars` only when the target host's variables or facts are available (facts must be gathered if you're accessing facts).
    
- Use `groups` for dynamic loops instead of hardcoding hostnames.
    
- Use `group_names` to apply logic based on a host's group membership.
    
- Use `ansible_play_batch` with `serial` deployments to understand which hosts are being processed.

# Summary

|Magic Variable|Purpose|
|---|---|
|`inventory_hostname`|Current host name from inventory|
|`inventory_hostname_short`|Short host name|
|`hostvars`|Access variables or facts from any host|
|`groups`|All inventory groups and their members|
|`group_names`|Groups for the current host|
|`ansible_play_hosts`|Hosts still active in the play|
|`ansible_play_batch`|Hosts in the current execution batch|
|`ansible_check_mode`|`true` when using `--check`|
|`ansible_diff_mode`|`true` when using `--diff`|
|`ansible_limit`|Inventory limit specified with `--limit`|

## Remember

- **`hostvars` → "Variables and facts of any host."**
    
- **`groups` → "All inventory groups."**
    
- **`group_names` → "Groups for this host."**
    
- **`inventory_hostname` → "Current host name from the inventory."**
    
- **`ansible_play_hosts` → "Hosts still participating in the play."**
    
- **`ansible_play_batch` → "Hosts being processed right now."**
    

These magic variables are essential for writing dynamic, reusable, and inventory-aware Ansible playbooks.
