# Ansible `ios_config` - Understanding `parents`

## What is `parents`?

The `parents` parameter in the `cisco.ios.ios_config` module specifies the **configuration context (parent configuration mode)** under which the commands in `lines` should be executed.

Think of it as navigating through the Cisco IOS CLI before running the configuration commands.

For example, when configuring an interface manually on a Cisco router:

```text
Router# configure terminal
Router(config)# interface FastEthernet0/0
Router(config-if)# description Connection to PC1
Router(config-if)# ip address 192.168.90.11 255.255.255.0
Router(config-if)# no shutdown
```

The command:

```text
interface FastEthernet0/0
```

is the **parent context**.

The remaining commands are executed inside that interface configuration mode.

In Ansible, this is represented using `parents`.

---

# Example Playbook

```yaml
---
- name: Demo on config ip address
  hosts: ciscoIOS
  gather_facts: false

  tasks:
    - name: config ip address
      cisco.ios.ios_config:
        lines:
          - "description {{ item.description }}"
          - "ip address {{ item.ip_address }} {{ item.subnet_mask }}"
          - "no shutdown"
        parents:
          - "interface {{ item.name }}"
      loop: "{{ interface_details }}"
      register: output

    - name: show the interface configured
      ansible.builtin.debug:
        msg: "{{ output }}"
```

# Understanding Each Section

## `lines`

```yaml
lines:
  - "description {{ item.description }}"
  - "ip address {{ item.ip_address }} {{ item.subnet_mask }}"
  - "no shutdown"
```

`lines` contains the configuration commands that Ansible sends to the Cisco device.

For every interface, Ansible executes:

```text
description Connection to Pc1
ip address 192.168.90.11 255.255.255.0
no shutdown
```

These commands **must be executed under the correct configuration mode**.

That is the purpose of `parents`.

---

## `parents`

```yaml
parents:
  - "interface {{ item.name }}"
```

For the first loop iteration,

```yaml
item.name = FastEthernet0/0
```

Ansible changes it to

```text
interface FastEthernet0/0
```

For the second iteration,

```yaml
item.name = FastEthernet2/0
```

Ansible changes it to

```text
interface FastEthernet2/0
```

# How `loop` Works with `parents`

The variable:

```yaml
interface_details:
  - name: FastEthernet0/0
    description: Connection to Pc1
    ip_address: 192.168.90.11
    subnet_mask: 255.255.255.0

  - name: FastEthernet2/0
    description: Connection to Pc2
    ip_address: 192.168.91.11
    subnet_mask: 255.255.255.0
```

During the first iteration,

```yaml
item:
  name: FastEthernet0/0
  description: Connection to Pc1
```

During the second iteration,

```yaml
item:
  name: FastEthernet2/0
  description: Connection to Pc2
```

Therefore,

```yaml
parents:
  - "interface {{ item.name }}"
```

automatically becomes:

```text
interface FastEthernet0/0
```

and later

```text
interface FastEthernet2/0
```

This allows a single task to configure multiple interfaces.

---

# Why `parents` is Needed

Without `parents`:

```yaml
lines:
  - description Connection to Pc1
```

Ansible would try to execute:

```text
description Connection to Pc1
```

from **global configuration mode**, which is invalid because `description` is an interface-level command.

Cisco IOS would return an error similar to:

```text
% Invalid input detected at '^' marker.
```

Using

```yaml
parents:
  - interface FastEthernet0/0
```

places Ansible in the correct configuration mode before executing the commands.

---

# Multiple Parent Levels

`parents` can contain multiple configuration levels.

Example:

```yaml
parents:
  - router ospf 1
  - address-family ipv4
```

Ansible navigates through both parent contexts:

```text
configure terminal
router ospf 1
 address-family ipv4
```

before executing the commands in `lines`.

# Summary

|Parameter|Purpose|Example|
|---|---|---|
|`lines`|Commands to configure|`ip address 192.168.1.1 255.255.255.0`|
|`parents`|Configuration mode where `lines` are executed|`interface GigabitEthernet0/0`|
|`loop`|Repeats the task for each item|Each interface in `interface_details`|
|`item`|Current element from the loop|One interface dictionary|

# Key Takeaways

- `parents` tells Ansible **which configuration mode** to enter before applying commands.
    
- Commands in `lines` are executed **inside** the parent context.
    
- Interface configuration requires `parents` because commands like `description`, `ip address`, and `no shutdown` are interface-level commands.
    
- `loop` allows the same task to configure multiple interfaces dynamically.
    
- Without `parents`, interface-specific commands would be executed in global configuration mode and fail.
    
- `parents` can contain one or more configuration levels, allowing Ansible to navigate nested Cisco IOS configuration modes automatically.
