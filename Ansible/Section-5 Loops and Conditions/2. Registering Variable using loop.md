# Registering Variables with `loop` in Ansible

## Overview

When a task is executed multiple times using the `loop` keyword, the `register` keyword stores the output of **every iteration** instead of only the last execution.

The registered variable contains a **`results`** list, where each list item represents the output of one loop iteration.

This is useful when you need to:

- Collect command outputs from multiple devices or interfaces.
    
- Process each result later in the playbook.
    
- Make decisions based on outputs from previous loop executions.
    

---

## Syntax

```yaml
- name: Run a task multiple times
  module_name:
    ...
  loop: "{{ list }}"
  register: result_variable
```

The registered variable will have the following structure:

```text
result_variable
└── results
    ├── Result of first iteration
    ├── Result of second iteration
    ├── Result of third iteration
    └── ...
```

---

# Example

```yaml
---
- name: Register variables with loop
  hosts: R1
  gather_facts: false

  vars:
    interfaces:
      - name: GigabitEthernet3/0
        ip: 192.168.75.11
        subnet: 255.255.255.0

      - name: GigabitEthernet4/0
        ip: 192.168.76.11
        subnet: 255.255.255.0

  tasks:

    - name: Fetch interface traffic and assign to a variable
      cisco.ios.ios_command:
        commands:
          - "show interface {{ item.name }} | include rate"
      register: interface_rate
      loop: "{{ interfaces }}"

    - name: Display the registered variable
      ansible.builtin.debug:
        var: interface_rate

    - name: Loop over the registered variable
      ansible.builtin.debug:
        msg: "{{ item.stdout[0] }}"
      loop: "{{ interface_rate.results }}"
```

---

# How It Works

## Step 1: Loop Through Interfaces

```yaml
loop: "{{ interfaces }}"
```

The task executes once for each interface.

Iteration 1:

```yaml
GigabitEthernet3/0
```

Iteration 2:

```yaml
GigabitEthernet4/0
```

---

## Step 2: Register the Output

```yaml
register: interface_rate
```

Since the task runs multiple times, Ansible stores every execution inside:

```yaml
interface_rate.results
```

instead of a single output.

---

## Step 3: Inspect the Registered Variable

```yaml
- debug:
    var: interface_rate
```

Example output (simplified):

```yaml
interface_rate:
  changed: false
  results:
    - item:
        name: GigabitEthernet3/0
      stdout:
        - "5 minute input rate 1000 bits/sec"

    - item:
        name: GigabitEthernet4/0
      stdout:
        - "5 minute input rate 2500 bits/sec"
```

Notice that:

- `results` is a list.
    
- Each list item contains:
    
    - the original `item`
        
    - command output (`stdout`)
        
    - return code (`rc`)
        
    - execution status (`failed`, `changed`, etc.)
        

---

# Accessing Individual Results

Loop through the registered results:

```yaml
- debug:
    msg: "{{ item.stdout[0] }}"
  loop: "{{ interface_rate.results }}"
```

Output:

```text
5 minute input rate 1000 bits/sec
5 minute input rate 2500 bits/sec
```

# Access Other Fields

Display the interface name:

```yaml
- debug:
    msg: "{{ item.item.name }}"
  loop: "{{ interface_rate.results }}"
```

Output:

```text
GigabitEthernet3/0
GigabitEthernet4/0
```

Display both the interface name and its output:

```yaml
- debug:
```

Output:

```text
GigabitEthernet3/0 -> 5 minute input rate 1000 bits/sec
GigabitEthernet4/0 -> 5 minute input rate 2500 bits/sec
```

# Practical Example 1: Ping Multiple IP Addresses

```yaml
vars:
  servers:
    - 8.8.8.8
    - 1.1.1.1

tasks:

- name: Ping servers
  ansible.builtin.command:
    cmd: "ping -c 1 {{ item }}"
  loop: "{{ servers }}"
  register: ping_result

- name: Show ping output
  ansible.builtin.debug:
    msg: "{{ item.stdout_lines }}"
  loop: "{{ ping_result.results }}"
```

# Practical Example 2: Check Multiple Files

```yaml
vars:
  files:
    - /etc/passwd
    - /etc/shadow

tasks:

- name: Check files
  ansible.builtin.stat:
    path: "{{ item }}"
  loop: "{{ files }}"
  register: file_status

- name: Display existence
  ansible.builtin.debug:
    msg: "{{ item.item }} exists = {{ item.stat.exists }}"
  loop: "{{ file_status.results }}"
```

Example output:

```text
/etc/passwd exists = True
/etc/shadow exists = True
```

# Key Points

- `register` saves the output of a task.
    
- When used with `loop`, Ansible stores **all iteration results** inside the `results` list.
    
- Access the original loop value using `item.item`.
    
- Access the module output using fields such as:
    
    - `item.stdout`
        
    - `item.stdout_lines`
        
    - `item.rc`
        
    - `item.failed`
        
    - `item.changed`
        
- To process each iteration, loop over the registered variable:
    

```yaml
loop: "{{ registered_variable.results }}"
```

---

# Summary

|Keyword|Purpose|
|---|---|
|`loop`|Executes a task multiple times using a list of items.|
|`register`|Stores the output of a task.|
|`results`|Contains the output from every loop iteration.|
|`item.item`|Refers to the original loop item.|
|`item.stdout`|Contains the command output for the current iteration.|
|`loop: "{{ registered_variable.results }}"`|Iterates through all registered results for further processing.|
