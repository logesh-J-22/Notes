# Ansible Notes: `gather_facts` and `gather_subset`

## What is `gather_facts`?

`gather_facts` is an Ansible playbook option that collects information (called **facts**) about managed hosts before running any tasks.

These facts include details such as:

- Hostname
    
- Operating System
    
- IP addresses
    
- CPU information
    
- Memory
    
- Disk information
    
- Network interfaces
    
- Python version
    
- Virtualization details
    

Ansible collects these facts using the `ansible.builtin.setup` module.

---

# Syntax

```yaml
- hosts: all
  gather_facts: true
```

or

```yaml
- hosts: all
  gather_facts: false
```

---

# Values of `gather_facts`

|Value|Description|
|---|---|
|`true`|Collect facts before running tasks (default)|
|`false`|Skip fact collection|

---

# Example 1: Gather Facts (Default)

```yaml
- name: Gather Facts Example
  hosts: servers
  gather_facts: true

  tasks:
    - name: Display hostname
      debug:
        msg: "{{ ansible_hostname }}"
```

When the play starts, Ansible automatically runs the `setup` module to collect facts.

---

# Example 2: Disable Fact Gathering

```yaml
- name: Cisco Show Command
  hosts: routers
  gather_facts: false

  tasks:
    - name: Show Version
      cisco.ios.ios_command:
        commands:
          - show version
```

### Why disable it?

Network devices (Cisco IOS, NX-OS, Junos, etc.) usually do not support the standard Linux fact-gathering process, so `gather_facts: false` is commonly used in network automation.

It also makes playbooks start faster when host facts are not needed.

---

# Viewing All Facts

You can display every collected fact using:

```yaml
- hosts: servers
  gather_facts: true

  tasks:
    - debug:
        var: ansible_facts
```

---

# Common Facts

|Fact|Description|
|---|---|
|`ansible_hostname`|Hostname|
|`ansible_os_family`|OS family|
|`ansible_distribution`|Linux distribution|
|`ansible_distribution_version`|OS version|
|`ansible_default_ipv4.address`|Primary IPv4 address|
|`ansible_processor_vcpus`|Number of virtual CPUs|
|`ansible_memtotal_mb`|Total memory (MB)|
|`ansible_architecture`|CPU architecture|

Example:

```yaml
- debug:
    msg: "{{ ansible_default_ipv4.address }}"
```

---

# What is `gather_subset`?

`gather_subset` controls **which facts** the `setup` module collects.

Instead of collecting every available fact, you can collect only the categories you need.

This improves playbook performance by reducing the amount of information gathered.

---

# Syntax

```yaml
- hosts: all
  gather_facts: true

  tasks:
    - name: Gather selected facts
      ansible.builtin.setup:
        gather_subset:
          - network
```

or

```yaml
gather_subset:
  - network
```

---

# Why Use `gather_subset`?

Suppose a server has hundreds of facts.

If you only need network information, collecting everything wastes time.

Instead:

```
Collect only network facts
        ↓
Faster playbook
        ↓
Less data transferred
```

---

# Example 1: Gather Only Network Facts

```yaml
- hosts: servers
  gather_facts: false

  tasks:
    - name: Gather network facts
      ansible.builtin.setup:
        gather_subset:
          - network

    - debug:
        msg: "{{ ansible_default_ipv4.address }}"
```

Only network-related facts are collected.

---

# Example 2: Gather Hardware Facts

```yaml
- hosts: servers
  gather_facts: false

  tasks:
    - name: Gather hardware facts
      ansible.builtin.setup:
        gather_subset:
          - hardware

    - debug:
        msg: "{{ ansible_processor }}"
```

---

# Example 3: Gather Minimal Facts

```yaml
- hosts: servers

  tasks:
    - name: Gather minimum facts
      ansible.builtin.setup:
        gather_subset:
          - min
```

This gathers only the essential facts, making it much faster than collecting everything.

---

# Common `gather_subset` Values

|Subset|Description|
|---|---|
|`all`|Collect all available facts (default)|
|`min`|Collect only essential facts|
|`network`|Network interfaces and IP addresses|
|`hardware`|CPU, memory, disks, architecture|
|`virtual`|Virtualization information|
|`facter`|Facts from Facter (if installed)|
|`ohai`|Facts from Ohai (if installed)|

---

# Excluding a Subset

You can exclude a subset by prefixing it with `!`.

Example:

```yaml
- hosts: servers

  tasks:
    - name: Gather all except hardware
      ansible.builtin.setup:
        gather_subset:
          - all
          - "!hardware"
```

This collects all facts except hardware-related facts.

---

# `gather_facts` vs `setup`

These two approaches both collect facts, but they differ in when and how they run.

## `gather_facts`

```yaml
- hosts: servers
  gather_facts: true
```

- Runs automatically at the beginning of the play.
    
- Collects facts before any tasks.
    

## `setup`

```yaml
- hosts: servers
  gather_facts: false

  tasks:
    - name: Gather facts manually
      ansible.builtin.setup:
```

- Runs only when you call it as a task.
    
- Lets you gather facts later in the play or gather only selected subsets.
    

---

# Best Practices

- Use `gather_facts: false` if your playbook does not need host facts.
    
- For network devices, `gather_facts: false` is the common choice unless you're using a network-specific facts module.
    
- Use `gather_subset: min` when you only need basic host information.
    
- Use `gather_subset: network` when working with IP addresses and interfaces.
    
- Use `debug: var=ansible_facts` to explore available facts.
    

---

# Summary

|Feature|Purpose|
|---|---|
|`gather_facts: true`|Automatically collect host facts before tasks|
|`gather_facts: false`|Skip automatic fact gathering|
|`setup` module|Gather facts manually during a play|
|`gather_subset: all`|Collect all available facts|
|`gather_subset: min`|Collect only essential facts|
|`gather_subset: network`|Collect network-related facts|
|`gather_subset: hardware`|Collect CPU, memory, and hardware facts|
|`!subset`|Exclude a fact subset (for example, `!hardware`)|

## Remember

- **`gather_facts` answers "Should Ansible collect facts automatically?"**
    
- **`gather_subset` answers "Which facts should be collected?"**
    

Use `gather_facts` to enable or disable automatic fact collection, and use `gather_subset` with the `setup` module to control the scope of the facts you gather.
