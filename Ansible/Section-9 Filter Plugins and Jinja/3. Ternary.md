Ternary lets us to write if else statement in a single line. 

# Ansible Ternary Filter

## Overview

The **`ternary`** filter in Ansible works like the **ternary operator** found in many programming languages.

It evaluates a boolean expression and returns one of two values.

### Syntax

```jinja2
{{ condition | ternary(true_value, false_value) }}
```

- **condition** → A boolean expression (`True` or `False`)
- **true_value** → Returned when the condition is `True`
- **false_value** → Returned when the condition is `False`

---

## Basic Example

```yaml
- name: Demonstrate ternary filter
  hosts: localhost
  gather_facts: false

  tasks:
    - name: Display message
      debug:
        msg: "{{ (10 > 5) | ternary('Condition is True', 'Condition is False') }}"
```

**Output**

```
ok: [localhost] => {
    "msg": "Condition is True"
}
```

---

# Practical Example

Suppose you want to check whether an interface is **up** or **down** based on the output of a Cisco IOS command.

## Playbook

```yaml
---
- name: Demo on Ternary Filter
  hosts: R1
  gather_facts: false

  tasks:

    - name: Check interface status
      cisco.ios.ios_command:
        commands:
          - show ip interface brief | include FastEthernet2/0
      register: output

    - name: Apply ternary filter
      ansible.builtin.debug:
        msg: "{{ ('up' in output.stdout[0]) | ternary('Interface is up', 'Interface is down') }}"
```

---

## How it Works

### Step 1

The command output might look like:

```
FastEthernet2/0    192.168.10.1    YES manual    up    up
```

The output is stored in:

```yaml
output.stdout[0]
```

### Step 2

The expression:

```jinja2
'up' in output.stdout[0]
```

returns either:

```text
True
```

or

```text
False
```

### Step 3

The ternary filter evaluates the result.

```jinja2
{{ ('up' in output.stdout[0]) | ternary('Interface is up', 'Interface is down') }}
```

If the expression is **True**

```
Interface is up
```

If the expression is **False**

```
Interface is down
```

# Another Example

Choose a configuration based on the device OS.

```yaml
vars:
  device_os: ios

tasks:
  - debug:
      msg: "{{ (device_os == 'ios') | ternary('Cisco IOS Device', 'Non-IOS Device') }}"
```

Output

```
Cisco IOS Device
```

# Example with Variables

```yaml
vars:
  vlan_exists: true

tasks:
  - debug:
      msg: "{{ vlan_exists | ternary('Skip VLAN creation', 'Create VLAN') }}"
```

Output

```
Skip VLAN creation
```

# Nested Ternary

Multiple conditions can be chained, though readability decreases.

```jinja2
{{ value == 1
   | ternary('One',
      value == 2
      | ternary('Two', 'Other')) }}
```

For multiple conditions, consider using `when` statements or dictionaries for better readability.

---

# Common Use Cases

- Display different messages.
- Choose configuration templates.
- Select commands based on operating system.
- Set variable values dynamically.
- Make playbooks more concise.

Example:

```yaml
vars:
  config_file: "{{ (ansible_network_os == 'cisco.ios.ios')
                   | ternary('ios.j2', 'generic.j2') }}"
```

---

# Tips

- The input to `ternary` **must evaluate to a boolean**.
- Use parentheses around complex expressions for clarity.
- For complex decision logic, prefer `when` statements instead of deeply nested ternary filters.

---

# Summary

| Expression | Result |
|------------|--------|
| `condition | ternary(A, B)` | Returns `A` if `condition` is `True`, otherwise `B` |
| `'up' in output.stdout[0]` | Checks whether the string `"up"` exists in the command output |
| `('up' in output.stdout[0]) \| ternary('UP','DOWN')` | Returns `UP` or `DOWN` based on the condition |

---

## Key Takeaway

The **`ternary` filter** is a concise way to perform inline conditional logic in Ansible templates. It is especially useful when assigning variables, selecting templates, or displaying status messages without writing separate `when` conditions.
