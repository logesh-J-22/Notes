# Ansible `to_json` and `to_nice_json` Filters

## Overview

Ansible variables are stored as Python data structures (dictionaries, lists, strings, integers, etc.). Sometimes you need to convert these variables into **JSON format**.

The **`to_json`** and **`to_nice_json`** filters serialize Ansible variables into JSON strings.

These filters are commonly used for:

- Saving variables to JSON files.
- Sending JSON payloads to REST APIs.
- Logging structured data.
- Debugging complex variables.
- Integrating with applications that accept JSON.

---

# `to_json`

The `to_json` filter converts an Ansible variable into a JSON-formatted string.

## Syntax

```jinja2
{{ variable | to_json }}
```

Example:

```jinja2
{{ router_details | to_json }}
```

---

# `to_nice_json`

The `to_nice_json` filter also converts a variable to JSON but formats it with indentation and line breaks for improved readability.

## Syntax

```jinja2
{{ variable | to_nice_json }}
```

Example:

```jinja2
{{ router_details | to_nice_json }}
```

# Demo Playbook

```yaml
---
- name: Demo on to_json
  hosts: R1
  gather_facts: false

  vars:

    router_details:
      ansible_host: 192.168.75.11
      dns_server: 10.10.10.10

      interface_details:

        - name: FastEthernet0/0
          description: Connection to PC1
          ip_address: 192.168.90.11
          subnet_mask: 255.255.255.0

        - name: FastEthernet2/0
          description: Connection to PC2 - Faulty
          ip_address: 192.168.91.11
          subnet_mask: 255.255.255.0

  tasks:

    - name: Display JSON output
      debug:
        msg:
          - "{{ router_details }}"
          - "{{ router_details | to_json }}"

    - name: Save JSON file
      copy:
        content: "{{ router_details | to_json(indent=2) }}"
        dest: "{{ playbook_dir }}/temp_files/router_details.json"

    - name: Save formatted JSON file
      copy:
        content: "{{ router_details | to_nice_json }}"
        dest: "{{ playbook_dir }}/temp_files/router_details_to_nice_json.json"
```

# Example 1 – Display Original Variable

```jinja2
{{ router_details }}
```

Output (YAML representation)

```yaml
ansible_host: 192.168.75.11
dns_server: 10.10.10.10

interface_details:

- name: FastEthernet0/0
  description: Connection to PC1
  ip_address: 192.168.90.11
  subnet_mask: 255.255.255.0

- name: FastEthernet2/0
  description: Connection to PC2 - Faulty
  ip_address: 192.168.91.11
  subnet_mask: 255.255.255.0
```

Notice that this is **YAML**, not JSON.

---

# Example 2 – Convert to JSON

```jinja2
{{ router_details | to_json }}
```

Output

```json
{"ansible_host":"192.168.75.11","dns_server":"10.10.10.10","interface_details":[{"name":"FastEthernet0/0","description":"Connection to PC1","ip_address":"192.168.90.11","subnet_mask":"255.255.255.0"},{"name":"FastEthernet2/0","description":"Connection to PC2 - Faulty","ip_address":"192.168.91.11","subnet_mask":"255.255.255.0"}]}
```

Characteristics:

- Valid JSON
- Single-line output
- Compact representation
- Ideal for APIs and data exchange

---

# Example 3 – Pretty JSON Using `indent`

The `to_json` filter accepts an `indent` parameter.

```jinja2
{{ router_details | to_json(indent=2) }}
```

Output

```json
{
  "ansible_host": "192.168.75.11",
  "dns_server": "10.10.10.10",
  "interface_details": [
    {
      "name": "FastEthernet0/0",
      "description": "Connection to PC1",
      "ip_address": "192.168.90.11",
      "subnet_mask": "255.255.255.0"
    },
    {
      "name": "FastEthernet2/0",
      "description": "Connection to PC2 - Faulty",
      "ip_address": "192.168.91.11",
      "subnet_mask": "255.255.255.0"
    }
  ]
}
```

This output is much easier for humans to read.

# Example 4 – Using `to_nice_json`

```jinja2
{{ router_details | to_nice_json }}
```

Output

```json
{
    "ansible_host": "192.168.75.11",
    "dns_server": "10.10.10.10",
    "interface_details": [
        {
            "description": "Connection to PC1",
            "ip_address": "192.168.90.11",
            "name": "FastEthernet0/0",
            "subnet_mask": "255.255.255.0"
        },
        {
            "description": "Connection to PC2 - Faulty",
            "ip_address": "192.168.91.11",
            "name": "FastEthernet2/0",
            "subnet_mask": "255.255.255.0"
        }
    ]

```

`to_nice_json` automatically formats the output for readability without requiring you to specify an indentation level.

# Saving JSON to a File

```yaml
- name: Save JSON
  copy:
    content: "{{ router_details | to_json(indent=2) }}"
    dest: router_details.json
```

Generated file:

```json
{
  "ansible_host": "192.168.75.11",
  "dns_server": "10.10.10.10"
}
```

---

# Saving Pretty JSON

```yaml
- name: Save Pretty JSON
  copy:
    content: "{{ router_details | to_nice_json }}"
    dest: router_details.json
```

This creates a human-readable JSON file that is easy to inspect or version control.

# Common Use Cases

## Save configuration to a JSON file

```jinja2
{{ router_details | to_json(indent=2) }}
```

---

## Send data to a REST API

```yaml
body: "{{ router_details | to_json }}"
```

Many REST APIs expect the request body to be a JSON string.

---

## Debug complex variables

```yaml
- debug:
    msg: "{{ router_details | to_nice_json }}"
```

This makes nested dictionaries and lists much easier to understand during troubleshooting.

---

## Store inventory data

```yaml
- copy:
    content: "{{ hostvars | to_nice_json }}"
    dest: inventory.json
```

Useful for exporting inventory variables for documentation or external processing.

# `to_json` vs `to_nice_json`

| Feature                      | `to_json`           | `to_nice_json` |
| ---------------------------- | ------------------- | -------------- |
| Produces valid JSON          | ✅                   | ✅              |
| Compact output               | ✅                   | ❌              |
| Pretty printed               | Optional (`indent`) | ✅              |
| Human readable               | With `indent`       | ✅              |
| Best for REST APIs           | ✅                   | ❌              |
| Best for configuration files | With `indent`       | ✅              |
| Best for debugging           | Possible            | ✅              |

---

# Best Practices

- Use **`to_json`** when sending data to APIs or applications that require compact JSON.
- Use **`to_json(indent=2)`** if you want formatted JSON with a specific indentation level.
- Use **`to_nice_json`** for debugging, logging, documentation, and configuration files where readability is more important than compactness.
- Remember that these filters return a **JSON string**, not a Python dictionary.

---

# Summary

| Expression | Result |
|------------|--------|
| `{{ var | to_json }}` | Compact JSON string |
| `{{ var | to_json(indent=2) }}` | Pretty-printed JSON with 2-space indentation |
| `{{ var | to_nice_json }}` | Human-readable JSON using Ansible's default formatting |

---

# Key Takeaway

The **`to_json`** and **`to_nice_json`** filters convert Ansible variables into JSON strings. Use **`to_json`** for compact machine-readable output or API requests, and use **`to_nice_json`** when you want clean, formatted JSON for debugging, documentation, or saving to files.
