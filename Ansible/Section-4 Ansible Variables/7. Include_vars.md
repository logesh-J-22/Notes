# Ansible Notes: `include_vars`


| Vars_files                       | Include_vars                             |
| -------------------------------- | ---------------------------------------- |
| Loaded at start                  | Loaded dynamically during play           |
| Used for static variable loading | Used for conditional and dynamic loading |
| No conditions possible           | conditions possible                      |



## What is `include_vars`?

`include_vars` is an Ansible module used to **load variables from one or more external files** into a playbook at runtime.

Instead of defining all variables inside a playbook, you can store them in separate YAML or JSON files and load them only when needed.

This makes playbooks:

- Cleaner
    
- More modular
    
- Easier to maintain
    
- Reusable across environments
    

---

# Why use `include_vars`?

Without `include_vars`, you might define variables directly in the playbook:

```yaml
vars:
  hostname: R1
  location: Bangalore
  ntp_server: 10.10.10.10
```

As the number of variables grows, the playbook becomes harder to manage.

A better approach is to store them in a file:

```text
vars/
└── router.yml
```

and load them using `include_vars`.

---

# Syntax

```yaml
- name: Load variables
  ansible.builtin.include_vars:
    file: vars/router.yml
```

---

# Example 1: Load Variables from a File

### Directory Structure

```text
project/
│
├── playbook.yml
└── vars/
    └── router.yml
```

### `vars/router.yml`

```yaml
hostname: R1
location: Bangalore
ntp_server: 192.168.1.100
```

### `playbook.yml`

```yaml
- hosts: localhost
  gather_facts: false

  tasks:
    - name: Load router variables
      ansible.builtin.include_vars:
        file: vars/router.yml

    - name: Display hostname
      debug:
        msg: "{{ hostname }}"

    - name: Display location
      debug:
        msg: "{{ location }}"
```

Output

```text
Hostname: R1
Location: Bangalore
```

---

# Example 2: Load Variables from Different Files

Directory

```text
vars/
├── dev.yml
├── test.yml
└── prod.yml
```

### `vars/dev.yml`

```yaml
hostname: DEV-R1
```

### Playbook

```yaml
- hosts: localhost

  vars:
    environment: dev

  tasks:
    - name: Load environment variables
      include_vars:
        file: "vars/{{ environment }}.yml"

    - debug:
        msg: "{{ hostname }}"
```

Output

```text
DEV-R1
```

This is useful for managing different environments (development, testing, production).

---

# Example 3: Load All Variable Files from a Directory

Directory

```text
vars/
├── ntp.yml
├── users.yml
└── network.yml
```

Playbook

```yaml
- hosts: localhost

  tasks:
    - name: Load all variable files
      ansible.builtin.include_vars:
        dir: vars
```

Ansible loads every supported variable file in the `vars/` directory.

---

# Example 4: Assign Variables to a Namespace

Sometimes multiple files contain variables with the same names.

Instead of loading them into the global variable space, you can use `name`.

### `router.yml`

```yaml
hostname: R1
location: Bangalore
```

Playbook

```yaml
- hosts: localhost

  tasks:
    - include_vars:
        file: vars/router.yml
        name: router

    - debug:
        msg: "{{ router.hostname }}"

    - debug:
        msg: "{{ router.location }}"
```

Output

```text
R1
Bangalore
```

Variables become:

```yaml
router.hostname
router.location
```

instead of:

```yaml
hostname
location
```

This helps avoid variable name conflicts.

# Example 5: Cisco IOS Configuration

### `vars/router.yml`

```yaml
hostname: R1
loopback_ip: 10.1.1.1
```

Playbook

```yaml
- hosts: routers
  gather_facts: false

  tasks:
    - include_vars:
        file: vars/router.yml

    - name: Configure hostname
      cisco.ios.ios_config:
        lines:
          - hostname {{ hostname }}

    - name: Configure Loopback
      cisco.ios.ios_config:
        parents: interface Loopback0
        lines:
          - ip address {{ loopback_ip }} 255.255.255.255
```

# File Formats Supported

`include_vars` supports:

### YAML

```yaml
hostname: R1
```

### JSON

```json
{
  "hostname": "R1",
  "location": "Bangalore"
}
```

# `include_vars` vs `vars_files`

## `vars_files`

```yaml
- hosts: all

  vars_files:
    - vars/router.yml
```

- Loaded before tasks start.
    
- Suitable when variables are always needed.
    

---

## `include_vars`

```yaml
tasks:
  - include_vars:
      file: vars/router.yml
```

- Executed as a task.
    
- Can be conditional.
    
- Can use loops.
    
- Can load different files dynamically.
    

---

# Conditional Loading

```yaml
- include_vars:
    file: prod.yml
  when: env == "prod"
```

Only loads the file when the condition is true.

---

# Loading Variables in a Loop

Directory

```text
vars/
├── router.yml
├── users.yml
├── ntp.yml
```

Playbook

```yaml
- hosts: localhost

  tasks:
    - include_vars:
        file: "{{ item }}"
      loop:
        - vars/router.yml
        - vars/users.yml
        - vars/ntp.yml
```

Each file is loaded during the loop.

---

# Best Practices

- Store variables in a dedicated `vars/` directory.
    
- Use meaningful file names such as `dev.yml`, `prod.yml`, or `router.yml`.
    
- Use `name:` to avoid variable collisions when loading multiple files.
    
- Use `include_vars` when variables depend on conditions, environments, or runtime decisions.
    
- Prefer `vars_files` when the variables are always required.
    

---

# Summary

|Option|Purpose|
|---|---|
|`file:`|Load variables from a single file|
|`dir:`|Load all variable files from a directory|
|`name:`|Store loaded variables under a namespace|
|`when:`|Load variables conditionally|
|`loop:`|Load multiple variable files dynamically|

---

# `include_vars` vs `vars_files`

|Feature|`include_vars`|`vars_files`|
|---|---|---|
|Executed as a task|✅ Yes|❌ No|
|Dynamic file selection|✅ Yes|❌ No|
|Supports `when`|✅ Yes|❌ No|
|Supports loops|✅ Yes|❌ No|
|Loads before tasks|❌ No|✅ Yes|

---

# Remember

- **`include_vars` = Load variables during playbook execution.**
    
- **`file:` = Load one variable file.**
    
- **`dir:` = Load every supported variable file in a directory.**
    
- **`name:` = Create a namespace (for example, `router.hostname`) to prevent variable conflicts.**
    

`include_vars` is especially useful when working with multiple environments, network device configurations, or large playbooks where variables are organized into separate files.
